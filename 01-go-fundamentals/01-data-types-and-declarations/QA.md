# 专题 01：数据类型与变量声明核心面试考点 (QA)

---

### Q1: Go 语言的“零值保障与零值可用（Make zero value useful）”哲学是什么？各基本类型零值是什么？有哪些工业级应用案例？
**标准深度解答**：
1. **零值（Zero Value）设计哲学**：
   - 彻底杜绝 C/C++ 中未初始化变量分配随机内存野指针引发的安全隐患；
   - Go 规范严格保证：声明但未显式初始化的变量，其内存会被运行时自动擦拭为二进制全零。
2. **基本数据类型零值一览**：
   - 数值类型（`int`, `float`, `complex`）：`0` / `0.0` / `(0+0i)`；
   - 布尔型（`bool`）：`false`；
   - 字符串（`string`）：空字符串 `""`（长度为 0，底层指针非非法悬垂）；
   - 复合引用与指针类型（`pointer`, `slice`, `map`, `chan`, `func`, `interface`）：统一为 `nil`。
3. **“零值可用”的标准库典范**：
   - **`sync.Mutex`**：定义 `var mu sync.Mutex`，零值即代表“未加锁”状态，无需类似 `Init()` 的构造函数，开箱即用；
   - **`bytes.Buffer`**：`var buf bytes.Buffer`，零值内部切片虽为空，但可立即安全调用 `buf.Write()` 进行数据追加；
   - **`sync.WaitGroup`**：`var wg sync.WaitGroup`，初始计数即为 0，直接 `Add` / `Wait`，无需初始化。

### Q2: 自定义类型定义（`type MyInt int`）与类型别名（`type MyInt = int`）有什么本质区别？
**标准深度解答**：
1. **语法与底层机制对比**：
   - **自定义类型（`type NewType OldType`）**：创造了一个**全新的独立类型**。尽管底层数据存储相同，但编译期类型检查将其视作完全不同的符号，两者之间赋值必须显式强制类型转换；
   - **类型别名（`type AliasType = OldType`，Go 1.9+ 引入）**：仅仅是给原有类型起了一个**等价的名字**，编译后其符号与原类型完全一致，无需转换即可互相自由赋值。
2. **方法集（Method Set）绑定差异**：
   - 可以给**自定义类型**定义新的接收者方法（`func (m NewType) Print() { ... }`）；
   - **无法**直接给基础类型的**类型别名**扩展新方法（编译器报错无法为内置非本地类型定义方法）。
3. **实际工程应用场景**：
   - 类型别名主要用于**大型项目重构与代码平滑解耦迁移**（如标准库中的 `byte = uint8` 与 `rune = int32`），允许将类从一个包迁移至另一个包而保证调用方的兼容性。

### Q3: `iota` 计数器的求值规则是什么？如何在企业工程中利用 `iota` 与左移位运算符实现多权限掩码（Bitmask）？
**标准深度解答**：
1. **`iota` 的求值核心原则**：
   - `iota` 是常量计数器，**在遇到 `const` 关键字时重置为 0**；
   - `const` 分组中每增加一行声明，`iota` 内部计数器自增 1，即使该行省略了赋值或使用了其他表达式；
   - 使用空白标识符 `_` 可以跳过指定索引值。
2. **基于位掩码的企业权限模型实现**：
   ```go
   const (
       PermissionRead   = 1 << iota // 1 << 0 = 0001 (1)
       PermissionWrite  = 1 << iota // 1 << 1 = 0010 (2)
       PermissionDelete = 1 << iota // 1 << 2 = 0100 (4)
       PermissionAdmin  = 1 << iota // 1 << 3 = 1000 (8)
   )
   ```
3. **位运算组合与鉴权**：
   - **授予权限（按位或 `|`）**：`userRole := PermissionRead | PermissionWrite`；
   - **验证权限（按位与 `&`）**：`hasWrite := (userRole & PermissionWrite) != 0`；
   - **撤销权限（位清空 `&^`）**：`userRole = userRole &^ PermissionWrite`。

### Q4: `byte` 与 `rune` 的本质区别是什么？使用 `len(str)` 与 `for range` 遍历含中文的字符串时底层机制有何不同？
**标准深度解答**：
1. **底层类型与语义边界**：
   - **`byte`**：等价于 `uint8`，占用 1 字节，用于处理原始网络字节流或 ASCII 单字节字符；
   - **`rune`**：等价于 `int32`，占用 4 字节，用于表示一个完整的 Unicode 码点（Code Point），原生支持中文、多语言及 Emoji 字符。
2. **`len(str)` 陷阱**：
   - Go 中 `string` 内部是 UTF-8 编码的字节数组切片指针结构；
   - `len(str)` 返回的是**底层的物理字节数（Byte Count）**，而非肉眼可见的字符个数！
   - 例如 `"你好"` 采用 UTF-8 编码，每个汉字占用 3 字节，因此 `len("你好") == 6`；计算字符数应使用 `utf8.RuneCountInString("你好") == 2`。
3. **两种遍历字符串方式的底层差异**：
   - **常规索引下标 `for i := 0; i < len(str); i++`**：每次访问 `str[i]` 得到的是**单字节 `byte`**。若字符串包含中文，汉字会被截断拆分成破碎字节，打印出现乱码；
   - **`for index, char := range str`**：Go 运行时内置了 UTF-8 解码器，每次迭代自动解码出一个完整的 **Unicode `rune` 字符**；注意此时索引 `index` 是该字符在字节数组中的起始字节偏移量，不一定是连续递增的（如处理 3 字节汉字时索引每次步进 3）。
