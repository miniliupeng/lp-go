# 专题 03：流程控制语句核心面试考点 (QA)

---

### Q1: `if` 和 `switch` 中的初始化简短声明（Init Statement）的作用域规则是什么？如何防范变量遮蔽（Shadowing）隐患？
**标准深度解答**：
1. **初始化语句的作用域约束**：
   - 语法形式：`if val, err := query(); err != nil { ... } else { ... }`；
   - 规则：在初始化语句中声明的变量，其有效生命周期严格限定在该 `if-else` 或 `switch` 块的词法作用域内，块外不可见；
   - **设计优势**：避免将仅用于错误校验的临时变量泄漏到外层函数体，大幅提升代码封装性与整洁度。
2. **变量遮蔽（Variable Shadowing）陷阱**：
   - 若外层函数体已存在同名变量（例如外层定义了全局或局部 `err`），在 `if` 初始化语句中使用 `:=` 会无意中声明一个局部的全新变量，遮蔽外层变量；
   - 在 `if` 内部为该变量赋值并不会影响外层变量，导致外层变量保持零值，引发隐蔽的业务逻辑 Bug；
   - **治理实践**：借助静态检查工具 `go vet -shadow` 或在 IDE 中开启 Shadowing 告警。

### Q2: Go 的 `switch` 语句相较于 C/Java 有哪些重大语言设计升级？`fallthrough` 的执行机制是什么？
**标准深度解答**：
1. **四大语言级革新**：
   - **默认自动 `break`**：每个 `case` 分支执行完后默认直接跳出 `switch`，彻底杜绝因漏写 `break` 导致向下穿透（Fallthrough Bug）的通病；
   - **支持多表达式匹配**：单个 case 支持逗号分隔的多个匹配项，如 `case 1, 2, 3:`；
   - **无条件 switch 模式**：省略表达式直接作为多分支 `if-else if` 的优雅替代方案；
   - **类型分支（Type Switch）**：支持 `switch v := i.(type)` 直接对接口进行类型推断与动态向下造型。
2. **`fallthrough` 机制与陷阱**：
   - 若业务确实需要向下穿透，必须显式声明 `fallthrough` 关键字；
   - **核心细节**：`fallthrough` 会**无条件执行下一个 case 的代码体，而完全不会去评估下一个 case 的匹配条件是否为真**！因此必须极其谨慎使用。

### Q3: Go 1.22 针对 `for` / `for range` 循环变量的作用域做出了什么革命性修复？旧版本闭包与并发引发 Bug 的根本原因是什么？
**标准深度解答**：
1. **Go 1.22 之前的历史痛点（单变量地址重用）**：
   - 在 Go 1.21 及更早版本中，整个循环只会在栈上分配**唯一的一个循环迭代变量**；
   - 每次循环仅仅是将新值覆盖写入该同一块内存地址；
   - **灾难场景**：若在循环体内启动 goroutine 或引用闭包指针，所有并发协程捕获的都是同一个内存地址。当协程真正被调度执行时，循环往往已结束，所有协程读取到的都是最终迭代的最后一个值：
     ```go
     // Go 1.21- 经典大坑：打印出的全部是切片的最后一个元素
     for _, val := range items {
         go func() { fmt.Println(val) }()
     }
     ```
2. **Go 1.22+ 革命性修复（每轮迭代独立分配）**：
   - 从 Go 1.22 起，语言规范正式修改：**循环的每一次迭代都会创建一个独立的全新变量实例**；
   - 上述闭包并发代码在 Go 1.22+ 下无需手动写 `v := val` 副本拷贝，即可原生保证每个协程捕获到正确的当前轮次值，彻底根除了 Go 诞生十余年来最常被调侃的语言设计陷阱。

### Q4: 带标签的 `break` 和 `continue`（Labeled Break/Continue）在嵌套循环或 `select/switch` 中如何正确使用？
**标准深度解答**：
1. **传统无标签 break 的局限**：
   - 在包含 `for` 循环内嵌 `select` 或 `switch` 的结构中，默认的 `break` 只能跳出最内层的 `select` 或 `switch`，而无法终止外层的 `for` 循环；
   - 许多初学者误以为在 `select` 内部写 `break` 能退出循环，结果导致程序陷入无法退出的死循环。
2. **带标签 break 的运行机制**：
   - 必须在目标外层循环语句上方定义标签（Label）：
     ```go
     OuterLoop:
         for {
             select {
             case <-ctx.Done():
                 // 跳出并终止由 OuterLoop 标识的外层 for 循环
                 break OuterLoop
             case data := <-ch:
                 process(data)
             }
         }
     ```
   - 带标签的 `continue OuterLoop` 则直接终止当前内层执行，跳转到外层循环开始下一次迭代。
