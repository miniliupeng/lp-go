# 专题 07：结构体与接口核心面试考点 (QA)

---

### Q1: Go 语言为什么坚决不引入 `class` 和继承（inheritance）？
**标准深度解答**：
1. **破局传统面向对象深层弊端**：传统的 `class` 继承模型容易导致极深的继承层次（Fragile Base Class 问题），子类往往被迫继承父类不需要的字段与方法，导致系统脆弱且紧耦合；
2. **组合优于继承（Composition over Inheritance）**：Go 提倡通过**结构体组合（Embedding）**实现代码复用，结构体职责单一、边界清晰；
3. **接口非侵入式正交解耦**：Go 的鸭子类型接口使实现方无需关心依赖哪个接口，消费方可随时根据自身需要定义最小接口契约（ISP 接口隔离原则），极大地提升了系统的可测试性与模块独立性。

### Q2: 结构体方法的值接收者（Value Receiver）和指针接收者（Pointer Receiver）有什么本质区别？
**标准深度解答**：
1. **内存与修改语义**：
   - **值接收者 (`func (u User) ...`)**：调用时会发生结构体字节级的值拷贝，函数内部修改仅影响局部副本，外部对象不受任何影响；
   - **指针接收者 (`func (u *User) ...`)**：调用时仅拷贝 8 字节的物理内存指针，函数内部修改直接作用于外部原对象。
2. **锁字段拷贝死锁风险**：若结构体内部包含 `sync.Mutex` 等同步原语，**严禁使用值接收者**，因为拷贝互斥锁会导致锁失效，引发灾难性数据竞争；
3. **方法集与接口匹配约束**：若类型的方法使用指针接收者定义，那么只有该类型的指针 `*T` 才拥有该方法；类型值 `T` 并不属于该方法集（详细机制参见阶段二 `02-04`）。

### Q3: 什么是鸭子类型（Duck Typing）？Go 的隐式接口有什么优缺点？
**标准深度解答**：
1. **核心定义**：“只要一个类型实现了接口声明的全部方法，它就自动满足该接口”。
2. **核心优势**：
   - **彻底解耦提供方与使用方**：第三方库无需知道未来会有什么接口，调用方可以按需定义微接口并包装第三方对象（Mock 测试极其方便）；
   - **避免繁琐继承树**：无 `implements` 样板代码，提升重构灵活性。
3. **潜在代价**：
   - 如果重构某个接口的方法签名，隐式实现的类型可能在编译时默默“失去”接口资格，需要编译器或静态分析工具辅助提示。
