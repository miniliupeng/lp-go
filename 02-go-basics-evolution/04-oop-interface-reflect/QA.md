# 专题 04：接口底层与反射机制大厂高频面试题

---

### Q1: 为什么将一个值为 nil 的结构体指针赋给接口后，接口与 nil 判断的结果为 false？

**标准回答**：
- **底层表示**：Go 语言中的接口结构（`iface` 或 `eface`）是一个双指针结构体（包含**类型表指针 `tab`/`_type`** 与 **具体数据指针 `data`**）。
- **比较判定法则**：一个接口变量与 `nil` 比较为 true 的**唯一条件是其类型指针和数据指针同时为 0x0 (nil)**。
- **事故根因**：当执行 `var err error = (*MyError)(nil)` 时，虽然数据指针 `data` 是 nil，但类型指针 `tab` 已被赋值为 `*MyError` 的类型元数据地址。因为类型信息存在，整个接口在逻辑上绝对不等于 nil。
- **最佳实践**：任何返回接口（如 `error`）的函数，在成功或无错误发生时，必须**显式直接 `return nil`**，切忌返回一个未初始化的自定义指针变量。

### Q2: 结构体的值接收者与指针接收者，其对应的方法集（Method Sets）有何规定？对接口实现有什么影响？

**标准回答**：
- **规范定义**：
  - 类型 `T`（值类型）的方法集只包含以 `(t T)` 为接收者的方法。
  - 类型 `*T`（指针类型）的方法集同时包含以 `(t T)` 和 `(t *T)` 为接收者的所有方法。
- **对接口实现的关键影响**：
  - 如果接口定义了方法 `M()`，而类型结构体使用的是指针接收者 `func (t *T) M()`。
  - 此时只有 `*T` 实现了该接口，`T` 并没有实现该接口！
  - 若尝试写 `var i Interface = T{}`，编译器会直接报错：`T does not implement Interface (M method has pointer receiver)`。必须赋值指针：`var i Interface = &T{}`。

### Q3: 反射（`reflect`）为什么性能较差？大厂在什么时候会使用反射？

**标准回答**：
- **性能开销根因**：
  1. **逃逸分析受限**：反射入参是 `any`（空接口），会强制引发对象装箱并导致大量数据逃逸到堆上，增加 GC 标记压力。
  2. **元数据查找与寻址**：反射需要在运行时解析类型的字段偏移、方法符号表等复杂元数据，无法享受编译期内联与寄存器传参优化。
  3. **动态安全校验**：每次读写或调用都要经历动态类型检查、可寻址性（CanSet）校验与切片参数封装。
- **大厂工程取舍**：
  - **业务高吞吐主链路（热路径）严禁高频使用反射**。
  - **通用框架与基础设施（冷路径）合理使用**：如 ORM 映射（GORM）、JSON 序列化反序列化、依赖注入容器（Uber Dig/Wire）、RPC 协议编解码等需要极高通用抽象的场景。
