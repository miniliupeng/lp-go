# 专题 02：向量数据库与 RAG 检索高频面试题 (QA)

### Q1：向量检索中的 HNSW（分层可导航小世界图）算法相比传统的 IVF-FLAT 有何优势？
**标准深度解析**：
1. **IVF-FLAT 原理与短板**：基于聚类中心划分 Voronoi 空间，查询时先找最近的若干聚类中心（`nprobe`），再在聚类内部暴算。短板是召回率（Recall）与查询时延极度依赖聚类分布，动态频繁插入新数据时需要重聚类重构索引，且很难在极高召回率（>98%）下保持毫秒级性能。
2. **HNSW 核心优势**：
   - 借鉴了跳表（Skip-List）的多层分层思想，上层节点稀疏用于快速大步长导航收敛，底层节点密集用于局部精准搜索；
   - 查询时延随向量规模呈对数级增长（$O(\log N)$），检索速度极快且召回率极高；
   - 原生支持动态增量插入，无需离线重聚类，是 Milvus、PGVector、Qdrant 的首选索引。缺点是内存开销（保留图指针边结构）比 IVF 稍大。

### Q2：RAG 系统中为什么要引入混合召回（Hybrid Search）？仅靠向量检索为什么会失败？
**标准深度解析**：
1. **纯向量检索的阿喀琉斯之踵**：
   - **专有名词与精确匹配失效**：如用户检索错误码 `ERR_SYS_50201`、产品零件序列号 `iPhone 16 Pro Max`、特定人名。Embedding 模型往往将其映射为泛化的“手机”或“系统错误”嵌入，反而把语义相近但编号错误的文档排在前面。
   - **语义泛化引发的伪相似**：“公司不允许远程办公”与“公司支持远程办公”两句话在嵌入空间距离极近，导致召回截然相反的虚假事实。
2. **混合召回解法**：通过 BM25 / 全文倒排索引保障关键词字面命中，通过稠密向量保障同义扩展与语义意图，再通过 RRF（倒数排名融合）或 Cross-Encoder Re-ranker 重排模型综合打分，大幅提升企业级问答的准确率与落地可信度。

### Q3：为什么工业界通常在 RAG 管道中先做 Top-50 初筛，再用 Cross-Encoder Re-ranker 重排模型打分？
**标准深度解析**：
1. **计算成本权衡**：
   - **Bi-Encoder（向量检索）**：文档向量预先离线计算入库，查询时仅需单次 Query 向量计算 + 余弦点积，计算复杂度低，支持从百万/千万级向量库瞬间初筛出候选集（如 Top-50）；但因为 Query 与 Document 在计算时互不感知（独立编码），交互深度有限。
   - **Cross-Encoder（重排模型）**：将 `[CLS] Query [SEP] Document` 拼接在一起输入深度 Transformer，通过全注意力机制计算深层交互得分，精准度极高；但单次计算耗时数毫秒甚至数十毫秒，无法直接在百万级库上全量运行。
2. **两阶段最佳实践**：Bi-Encoder 负责“快召回”（高吞吐、毫秒级），Cross-Encoder 负责“精排序”（小集合深层对齐），兼顾系统高并发吞吐与极致答题准确度。
