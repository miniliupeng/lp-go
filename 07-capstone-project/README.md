## 📌 项目定位：`ai-gateway-service`（高并发流式 AI 智能网关服务）

作为本教程的**唯一压轴综合实战项目**，本项目拒绝玩具式 Demo，严格按照国内头部大厂（字节跳动、腾讯、美团、阿里等）企业级生产规范研发。
其核心使命是将前四个阶段沉淀的 **20 个硬核单点技术**（运行时调度、内存GC优化、并发锁、高并发中间件、微服务可靠性治理、流式反压、RAG混合重排与Agent）熔炼为一个**高内聚、高可用、可直接写入个人简历并经得起大厂 P7/P8 (T1/T2) 资深面试官连环深挖的工业级项目**。

## 🔬 深度与广度：覆盖全教程核心技术栈

| 核心技术模块 | 对应教程阶段 | 企业级生产落地场景 | 解决的线上故障与痛点 |
| :--- | :--- | :--- | :--- |
| **内存与 GC 极致优化** | 阶段零 & 阶段一 | • `fmt.Appendf` 原生切片追加<br>• `sync.Pool` 报文对象池化复用 | 杜绝传统 `+` 或 `fmt.Sprintf` 造成的大量小对象堆分配与 GC 频繁 STW 抖动 |
| **高并发防击穿** | 阶段二（Redis模式）| • `SingleFlight` 热点 Prompt 并发合并<br>• 租户级别令牌桶（Token Bucket） | 解决万级突发用户提问相同问题时的缓存击穿风暴，保护上游模型算力 |
| **微服务稳定性三板斧** | 阶段三（治理模式）| • 自适应三态断路器（Circuit Breaker）<br>• W3C `traceparent` 上下文透传 | 上游模型宕机或超时时快速拉闸降级，防止协程堆积雪崩；全链路按 TraceID 串联排障 |
| **AI 原生流式网关** | 阶段四（AI原生） | • 有界 Channel 超时网络反压（Backpressure）<br>• 监听 `r.Context().Done()` 级联中断 | 彻底解决弱网客户端消费慢撑爆网关内存引发的 OOM；客户端关掉页面时立即中断上游计费 |
| **私域 RAG 混合重排** | 阶段四（向量RAG）| • 稠密向量余弦相似度 + BM25 词频匹配<br>• RRF（倒数排名融合算法） | 解决纯向量检索对专有名词、工单号不敏感的致命缺陷，消灭大模型回答幻觉 |
| **工程底座与运维标准** | 阶段五（综合实战）| • `os.Signal` 优雅停机（Graceful Shutdown）<br>• 100% 通过 `go test -race` 并发竞争检验 | 容器热升级/发布时零请求丢弃，平滑排空所有正在推送的 SSE 长连接 |

## 🚀 落地推进与验收标准

1. **第一阶段：核心代码全量落地**
   - 编写 `cmd/`, `configs/`, `pkg/`, `internal/` 所有业务代码；
   - 保证结构严谨，每一个结构体、函数均具备标准注释；
   - 保证代码最简洁，杜绝冗余样式与无用变量。
2. **第二阶段：端到端单测与基准性能实测**
   - 覆盖所有核心场景：普通请求、SSE 流式推流、限流拒绝、熔断状态转移与恢复、反压丢弃、客户端中途主动断开；
   - 运行 `go test -race ./...` 保证 **0 数据竞争（Zero Data Race）**；
   - 运行 `go test -bench=. -benchmem`，产出真实的 QPS、TTFT（首字时延）与内存逃逸指标。
