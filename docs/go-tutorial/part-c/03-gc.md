# 03 GC

源码依据：Go 1.27.1 的 `runtime/mgc.go` 文件头、`runtime/mbarrier.go` 的混合写屏障注释，以及 `runtime/debug.SetMemoryLimit` 的文档。

## 核心原理

默认垃圾回收器是**并发的、精确的、非分代的、非整理的标记-清除**。分配按大小分档，每个 P 有自己的缓存，常见路径不加锁。

它不是 Green Tea GC。本工具链里 Green Tea 由 `GOEXPERIMENT=greenteagc` 打开；默认构建使用 `internal/goexperiment/exp_greenteagc_off.go`，其中 `GreenTeaGC` 为 false。面试先讲默认收集器。被追问实验特性时，说明它不是默认、API 和效果都不要背成已发布的承诺。

`mgc.go` 里的周期是：

1. **清扫终止**：短暂 STW，把上一轮还没扫的 span 扫完。若这轮开始得比预期早，才会有未扫 span。
2. **标记**：STW 把阶段设为标记、打开写屏障和辅助标记（mutator assist）、把根任务入队。然后恢复世界。根包括所有栈、全局变量，以及运行时数据结构里的堆指针。扫描一个栈时会停住对应的 goroutine。灰色对象被扫成黑色，它指向的对象再标灰。分布式终止发现没有灰对象之后进入标记终止。
3. **标记终止**：再一次 STW，关掉 worker 和 assist，做 mcache 刷新这类收尾。
4. **清扫**：关掉写屏障，恢复世界。清扫与用户代码并发：后台 goroutine 在扫，分配时如果还缺 span，分配者自己也会先扫够再拿。标记阶段新分配的对象直接是黑色；清扫开始之后新对象是白色。

## 写屏障

`runtime/mbarrier.go` 写的是混合屏障，不是「每次指针写入都把新旧两个对象都涂黑」这么简单：

```text
writePointer(slot, ptr):
    shade(*slot)                 // Yuasa 删除屏障：被覆盖的旧指针
    if current stack is grey:
        shade(ptr)               // Dijkstra 插入屏障：栈还是灰色时，新指针也要涂
    *slot = ptr
```

栈还没扫完、仍是灰色时，插入部分才需要。栈扫完变黑之后，删除屏障负责旧指针。这是 Go 1.8 以后的混合写屏障，用来缩短 STW 期间的栈扫描。

## GOGC 与内存上限

`debug.SetGCPercent` 的文档：当「本轮新分配的数据 / 上一轮结束后仍存活的数据」达到这个百分比，就触发下一轮。环境变量 `GOGC` 未设置时初始值是 100。设成负数等于关掉按比例触发，但内存上限仍然有效。

`debug.SetMemoryLimit` 是软上限，单位字节。运行时会提高回收频率，并更积极地把内存还给操作系统。`GOGC=off` 时这个上限仍然生效。它统计的是运行时映射、管理、尚未释放的内存，**不包括** Go 二进制本身、C 代码分配的内存，也不包括 `syscall.Mmap` 出去、不由运行时管理的映射。文档给出的表达式是：

```text
runtime.MemStats.Sys - runtime.MemStats.HeapReleased
```

用 `runtime/metrics` 则是 `/memory/classes/total:bytes` 减去 `/memory/classes/heap/released:bytes`。

传入负数不会修改上限，只返回当前值。初始值是 `math.MaxInt64`，除非设置了 `GOMEMLIMIT`。后缀 `KiB`、`MiB` 等按 2 的幂。上限设得比当前用量还低时，GC 会几乎不停，但程序仍应能往前走。

`ReadMemStats` 会短暂 STW。线上持续打点优先用 `runtime/metrics`。

## 可运行示例

```bash
go test ./docs/go-tutorial/examples/partc/gcinfo -count=1
```

测试把上限设成 512 MiB，再用负数参数读回，并在结束时恢复原值。它不调用 `SetGCPercent(-1)`，避免把整个进程的 GC 关掉。

## 面试常问

- 是分代吗、会整理吗：默认收集器两者都不是。
- STW 发生在哪：清扫终止和标记终止，用来打开或关掉写屏障、做终止，不是整轮标记都停世界。
- 写屏障涂的是什么：总是涂被覆盖的旧对象；栈仍为灰色时再涂新对象。
- `GOMEMLIMIT` 包不包括 cgo 堆：不包括。

## 对比陷阱

- 把 Green Tea 说成 Go 1.27 的默认 GC。
- 说「Go 的 GC 没有 STW」。两次短 STW 还在。
- 用 `MemStats.HeapAlloc` 一个数判断泄漏。要看分配曲线、`inuse` 和 profile，见 [性能一章](07-pprof-trace-bench.md)。
