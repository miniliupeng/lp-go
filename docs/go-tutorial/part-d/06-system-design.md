# 06 系统设计题里的 Go 落地

设计题要落到数据怎么放、并发怎么保护、失败和过期怎么处理，以及这一版故意没做的事。这一章用进程内短链把这四句说完。实现是 [shorturl](../examples/partd/shorturl/short.go)。

## 短链现在做了什么

`Put` 给 URL 分配短码，`Resolve` 换回来。测试注入时钟，TTL 是 1 分钟。

- 短码是递增计数的 62 进制。字母表是 `0-9`、`a-z`、`A-Z`。`seq` 从 0 开始，第一次 `Put` 先加 1，所以第一个码是 `"1"`，另一个 URL 得到 `"2"`。测试锁住了这两个字符串。
- 同一个 URL 在未过期时走 `byURL`，返回原来的短码。重复提交不会制造一串新码。
- `ttl > 0` 时把到期时间记成 `now().Add(ttl)`。`Put` 和 `Resolve` 先丢掉已到期的记录。条件是 `!now.Before(expires)`，所以到期时刻本身就算过期。到期后再 `Put` 同一个 URL，计数还在涨，得到的是新短码。
- `ttl <= 0` 表示不过期，`dropExpiredLocked` 直接返回。
- 空字符串返回错误，不分配短码。
- 两张 map 和计数都在同一把 `Mutex` 后面。过期扫描会在这把锁里看完所有记录。

进程退出后数据就没了。短码可以预测，因为下一个就是计数加一。`encode` 后面的循环会在短码已经存在时继续加计数；在 `uint64` 回绕之前，递增的 62 进制编码不会撞上自己刚发出去的码。循环是留给回绕、以及以后改成随机码时用的。

## 短链题要补上的边界

把这版实现说完之后，主动补上下一版会改什么。

**码的空间。** 62 进制 6 位是 `62^6 = 56,800,235,584`，大约 568 亿。空间大不等于没有冲突。线上改成随机或对 URL 做哈希时，插入必须处理「这个码已经给了别人」：数据库唯一约束失败就换一个码重试。递增计数还会暴露生成顺序，不要在公开服务里用它。

**过期后能不能立刻把码给别人。** 本实现过期即从两张 map 删除，计数不回头，刚过期的递增码不会马上发给下一个 URL。随机码没有这个性质，必须单独避免把刚过期的码立刻绑到另一个 URL，否则旧的书签会打开新的页面。

**跳转。** 查到 URL 之后用 302 或 307 把浏览器送过去。不要用 301：浏览器会长期记住永久跳转，短链过期或改了目标之后，用户仍可能走到旧地址。缓存头决定中间代理会不会把这次跳转存下来。这是 HTTP 的语义，不是 map 的语义。

**恶意 URL。** 写入前做校验。跳转失败时不要把内部错误原文回给用户。

**规模。** 锁里扫全表只适合这个教学进程。记录变多之后，过期改成惰性删除加上后台按时间分批扫，批量删除不要和在线的 `Resolve` 抢同一把锁直到扫完。持久化用数据库的唯一约束。热门短码再加一层带 TTL 的缓存，未命中时用 [singleflight](03-cache-ratelimit.md) 合并。

## 另外两道题怎么落到 Go

**全局限流。** [令牌桶](03-cache-ratelimit.md) 是单机限额。全局限额的计数要放在所有实例都能原子更新的地方，常见是 Redis 的一个键。Redis 不可用时有两种事先说清的策略：失败开放，请求继续走，保护的是可用性；失败关闭，请求被拒绝，保护的是后面的服务。单机桶的测试通过，不能把它说成全局限流。

**任务队列。** 至少一次投递意味着同一条任务可能被处理两次。消费者用任务 id 做去重，处理完再确认。确认放在处理之前，进程会在处理中途丢掉任务。消费者看 `context`：`Shutdown` 时停止取新任务，已经取到的要么做完，要么把可见性超时交还给队列。并发度可以用带缓冲的 channel 当计数信号量，缓冲容量就是同时执行的上限。这个用法在内存模型里是允许的，见 [内存一章](../part-c/01-memory-escape.md)。

**上传。** body 用 `http.MaxBytesReader` 限制大小。写盘路径用 `os.Root` 限制在一个目录树里，见 [JSON 与文件](../part-b/01-cli-files-json.md)。超时用 `ReadHeaderTimeout`，不要用一个很短的 `ReadTimeout` 把合法的大 body 掐掉。见 [net/http](01-net-http.md)。

## 面试时的四句话

数据放在两张 map 里，短码是递增的 62 进制。并发靠一把 `Mutex`，过期扫描也在这把锁里。到期时刻算过期，过期后再写入得到新码。这一版没有持久化、没有不可预测的短码，也没有跨进程限额。
