# 面试题库

先合上正文，口头回答。再按采分点给自己打分。采分点只包含本教程写过、并且能在 Go 1.27.1 的文档或示例里对上的内容。某一版编译器的英文提示、某一台机器的 `ns/op`，都不是采分点。

仓库原有的 `00-` 到 `07-` 专题可以当加练。答这套题不需要背那些目录里的基准数字。

## 怎么计分

每题 2 分。答到全部采分点得 2 分，答到一半得 1 分。踩了「失分」里的说法，该题 0 分。

---

## A. 语言与标准库

### A1. 声明一个 `var s string` 却不赋值，读它得到什么？

考察：零值。

采分点：得到 `""`，不是未定义内存。数值是 0，`bool` 是 false，指针、切片、map、channel、接口、函数是 nil。

失分：说 Go 的局部变量是垃圾值。

### A2. `0b1110 &^ 0b0110` 等于多少？`-1/2` 呢？

考察：运算符。

采分点：`&^` 按位清除，结果是 `0b1000`。整数除法向零截断，`-1/2` 是 `0`。`++` 是语句。`&&` / `||` 短路。

失分：说 Go 的整数除法向负无穷取整，或者把 `++` 写进表达式。

### A3. `len("中")` 和 `[]rune("中")` 的长度？

考察：字符串是字节序列。

采分点：`len` 是 3 个字节；rune 个数是 1。`s[i]` 是字节。

失分：说 `len` 对所有字符串返回字符数。

### A4. 切片和数组差在哪？`append` 之后别的切片会变吗？

考察：切片头和底层数组。

采分点：数组长度是类型的一部分。切片是指针、长度、容量。容量够时 `append` 写进同一块底层数组，共享它的切片能看见。容量不够会换新数组。

失分：背一个永远成立的扩容倍数。

### A5. map 的遍历顺序？两个 goroutine 一起写会怎样？

考察：map 语义。

采分点：遍历顺序随机。并发写 panic。实现从 Go 1.24 起是 Swiss Table 风格，这是实现细节。

失分：说 `sync.Map` 在所有场景都比加锁的 map 快。`sync.Map` 只针对「写一次读很多次」或「键按 goroutine 分开」。

### A6. `defer` 的顺序？参数何时求值？

考察：defer。

采分点：后进先出。参数在执行到 `defer` 那一行时求值。

失分：说参数在函数返回时才求值。

### A7. 为什么解析失败返回 `error`，而不是 `panic`？

考察：错误处理。

采分点：`panic` 留给不变量被破坏。`fmt.Errorf` 用 `%w` 才能被 `errors.Is` / `As` 解开。哨兵用 `Is`，带字段的类型用 `As`。

失分：用字符串比较错误文本来做分支。

### A8. `encoding/json` 和 `encoding/json/v2` 对重复键有什么差别？

考察：Go 1.27 的 JSON。

采分点：v1 API 仍是后者覆盖前者。v2 的 `Unmarshal` 拒绝重复键。v1 的实现在 Go 1.27 换成了 v2，但 v1 语义保留。`GOEXPERIMENT=nojsonv2` 是过渡开关。

失分：说导入路径没变所以行为全部没变，或者编一个不存在的默认字段。

## B. 泛型、接口、context

### B1. `comparable` 和 `~[]E` 分别表示什么？

考察：约束。

采分点：`comparable` 可以用 `==`，能做 map 键。`~[]E` 允许底层类型是切片的具名类型。

失分：说 `any` 的值都能做 map 键。

### B2. Go 1.27 的泛型方法能放进接口吗？

考察：语言变更。

采分点：方法可以自带类型参数。接口方法不能声明类型参数，泛型方法也不能用来实现接口方法。

失分：写一个带类型参数的接口方法并声称能编译。

### B3. `for range` 一个 `iter.Seq` 时，`break` 之后迭代器还能继续 `yield` 吗？

考察：Go 1.23 迭代器。

采分点：`break` 让 `yield` 返回 false。迭代器必须停，再调用 `yield` 会 panic。

失分：说 `break` 只是调用方的事，迭代器可以继续发完剩下的值。

### B4. 值接收者的方法，什么样的值能放进接口？

考察：方法集。

采分点：`T` 的方法集只有值接收者。`*T` 两者都有。可寻址的值上，编译器会自动取地址；放进接口之后不会。

失分：说「有指针方法的类型，值永远调不了这个方法」。

### B5. `var p *T = nil` 再赋给 `error`，`err == nil` 吗？

考察：typed nil。

采分点：不是 nil 接口。动态类型是 `*T`。表示没有错误时要返回裸 nil。

失分：说所有等于 nil 的指针放进接口后还是 nil。

### B6. 取消 context 会不会把 goroutine 杀掉？

考察：context。

采分点：不会。函数或它调用的库必须观察 `Done`。`Err()` 是 `Canceled` 或 `DeadlineExceeded`。`Cause` 才是附加原因。

失分：说 `cancel()` 等价于 `runtime` 把 G 停掉。

### B7. `reflect.ValueOf(n).CanSet()` 为什么是 false？

考察：反射。

采分点：传进去的是副本，不可寻址。要改就传入指针再 `Elem()`。未导出字段也不能 `Set`。

失分：说 `SetInt` 对任何 `Int` kind 都成功。

## C. 运行时与并发

### C1. G、M、P 各是什么？M 在系统调用里还拿着 P 吗？

考察：GMP。

采分点：G 是 goroutine，M 是线程，P 是执行 Go 代码所需的资源。执行 Go 代码必须有 P。阻塞在系统调用里的 M 可以不持有 P。

失分：说 G 就是线程，或 `GOMAXPROCS` 是最大线程数。

### C2. 没有函数调用的死循环还能被抢占吗？测试 `sched` 证明了什么？

考察：抢占。

采分点：Unix 上异步抢占用 `SIGURG`，所以没有调用的循环也可以被抢占。仓库里的测试循环含有原子读取，那是同步安全点，它只证明一个 P 时对方 G 不会被饿死。

失分：说这个测试抓到了 `SIGURG`。

### C3. 默认 GC 是分代的吗？STW 在什么时候？

考察：GC。

采分点：并发、精确、非分代、非整理的标记-清除。STW 在清扫终止和标记终止。标记阶段新对象是黑色。Green Tea 不是默认，要 `GOEXPERIMENT=greenteagc`。

失分：说整轮标记都停世界，或说 Go 1.27 默认已经是 Green Tea。

### C4. 混合写屏障涂哪些指针？

考察：写屏障。

采分点：总是涂被覆盖的旧指针。当前栈还是灰色时，再涂新写入的指针。

失分：说每一次写入都无条件把新旧对象都涂黑，不提栈的颜色。

### C5. `GOMEMLIMIT` 统计哪些内存？

考察：内存上限。

采分点：`MemStats.Sys - HeapReleased`。不包括二进制、C 分配和运行时不管理的 `mmap`。负数参数只读取当前上限。`GOGC` 关掉之后上限仍然有效。

失分：说它能限制 cgo 堆。

### C6. 向已关闭 channel 发送、关闭 nil channel、从已关闭 channel 接收，各发生什么？

考察：channel。

采分点：发送 panic，`close(nil)` panic，接收得到零值且 `ok` 为 false。缓冲里剩下的值会先被取完。nil channel 的发送和接收永远阻塞，在 `select` 里不会被选中。

失分：说 `close` 会让发送方收到一个错误值。

### C7. 两个 select case 同时就绪，走哪一个？

考察：select。

采分点：伪随机，不能依赖源码顺序。

失分：说按书写顺序。

### C8. 无缓冲 channel 的发送和接收，谁 synchronized before 谁？

考察：内存模型。

采分点：发送 synchronized before 对应接收完成。接收 synchronized before 对应发送完成。所以它是一次握手。容量至少为 1 时，不能靠一次发送去保证发送方还写过的其他变量已经被接收方看见。容量 C 时，第 k 次接收 synchronized before 第 k+C 次发送完成。

失分：说任何 channel 发送都自动把发送方之前的所有写同步给接收方，不提缓冲。

### C9. Mutex 什么时候进入饥饿模式？

考察：锁。

采分点：正常模式下手被唤醒的等待者要和新来的 goroutine 竞争。超过 1ms 进入饥饿模式，解锁时把锁直接交给队首。锁不可重入，使用后不能复制。

失分：编一个不是 1ms 的阈值，或说 Mutex 可重入。

### C10. `WaitGroup.Add` 为什么不能写在子 goroutine 的第一行？

考察：WaitGroup。

采分点：`Wait` 可能在 `Add` 之前就看到计数为 0 并返回。`Add` 要发生在 `Wait` 观察之前。Go 1.27 的 `Go` 方法内部会先 `Add`。计数变负会 panic。

失分：说 `Wait` 会一直等到将来的 `Add`。

### C11. `sync.Pool` 能当缓存吗？

考察：Pool。

采分点：不能。GC 可以丢掉池里的对象。`New` 只在取空时调用。

失分：说 `Put` 之后 `Get` 一定拿回同一块内存。

### C12. 原子操作的内存序是什么？

考察：atomic。

采分点：B 观察到 A 的效果，则 A synchronized before B；全部原子操作有一个顺序一致的总顺序。和 C++ SC 原子、Java `volatile` 同类。32 位平台上优先用 `atomic.Int64`，避免自己对齐。

失分：声称标准库原子默认是 relaxed。

## D. 工程与设计

### D1. `ReadTimeout` 和 `ReadHeaderTimeout` 的差别？

考察：HTTP 超时。

采分点：`ReadTimeout` 包含 body。`ReadHeaderTimeout` 只限制读头，读完会重置读截止时间。它为 0 时改用 `ReadTimeout`。大上传不要靠一个很短的 `ReadTimeout`。

失分：说四个字段为 0 都表示「使用默认的 30 秒」。0 表示不额外设置，具体回退关系要按字段区分。

### D2. `Shutdown` 会等到 Hijack 的连接结束吗？

考察：优雅退出。

采分点：不会。它先关 Listener 和空闲连接，再等活跃连接回到空闲。不打断正在跑的 Handler。`Serve` 返回 `ErrServerClosed`。ctx 先到期则返回 ctx 的错误。

失分：说 `Shutdown` 会取消每个请求的 context 并立刻断开 WebSocket。

### D3. `*sql.DB` 和 `*sql.Tx` 哪个能并发用？

考察：database/sql。

采分点：`DB` 是池，可以并发。`Tx` 绑在一条连接上，不要并发用同一个 `Tx`。`Rows` 必须关闭。没有行是 `sql.ErrNoRows`。

失分：说 `Open` 的返回值是一条连接。

### D4. 教学驱动 `tutorialkv` 在两个事务写同一个键时做什么？

考察：你有没有把示例说成真正的数据库。

采分点：后提交的覆盖先提交的，没有冲突检测。不同的键可以都留下。读的是开始时的快照，本事务能读到自己的写。这不是 MySQL 的隔离级别。

失分：说它实现了可串行化。

### D5. 令牌桶的 `burst` 是什么？singleflight 保存结果吗？

考察：限流和击穿。

采分点：`burst` 是桶容量，所以允许突发。补充量是 `elapsed * rate`，不超过容量。singleflight 只合并正在进行的那一次，函数返回后不保留结果。它不解决「缓存一个不存在的键」。

失分：说 singleflight 等于带 TTL 的缓存。

### D6. 熔断器半开时能放进几个请求？

考察：状态机。

采分点：这版实现同时只允许一个探测。成功则关闭并清零；失败则重新打开并重算冷却时间。它没有把 4xx 排除在失败之外。

失分：说半开会把流量恢复到 50%。

### D7. 为什么重试创建订单危险？

考察：幂等。

采分点：没有幂等键的写可能双份。只重试幂等操作，并把重试算进入口超时。熔断打开时不要继续重试。

失分：说所有 HTTP 请求都可以安全重试三次。

### D8. 短链这版实现故意没做什么？

考察：设计边界。

采分点：没有持久化；短码是递增计数，会暴露顺序；过期是进程内一把锁。线上要换成随机码加冲突重试、数据库唯一约束，以及热 key 缓存。单机令牌桶不是全局限额。

失分：把 `shorturl.Store` 描述成可以水平扩展的服务。

### D9. `goroutineleak` 发现不了哪种泄漏？

考察：Go 1.27 profile。

采分点：它找的是堵在同步原语上、并且该原语从可运行的 G 到不了的情况。经过全局变量或可运行 G 的局部变量仍可达的阻塞，不在范围内。profile 是采样或可达性判断，不是数学上的全部泄漏集合。

失分：说打开这个端点就能列出所有泄漏的 goroutine。

### D10. 无竞争程序的执行模型叫什么？有竞争时 Go 和 C 一样吗？

考察：内存模型总纲。

采分点：DRF-SC，看起来像轮流在一个处理器上执行。有竞争时，实现可以报告并终止；否则不超过机器字的读必须看到某个真正写入过的值。竞争仍是 bug。goroutine 退出本身不是同步事件。

失分：说 Go 的数据竞争和 C 一样，编译器可以做任何事；或者说竞争在 Go 里是无害的。
