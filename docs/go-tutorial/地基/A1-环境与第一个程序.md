# A1 环境与第一个程序

本章假设你能打开终端。示例在模块 `tutorial` 里运行，`go.mod` 写的是 **Go 1.27.1**。main 上的工具链专题把安装、编辑器、编译和模块拆成四讲；这里收成一章，把会在后面反复用到的命令一次讲清。

## 这一章你要会什么

装上官方 Go，分清 `GOROOT`、`GOPATH`、模块和工具链版本，用 `go run` 跑通第一个程序，并知道格式化该调用哪一个命令。

## 安装和 PATH

从 [https://go.dev/dl/](https://go.dev/dl/) 安装官方发行版。Linux 上常见做法是把压缩包解到 `/usr/local/go`，把 `/usr/local/go/bin` 加进 `PATH`。macOS 和 Windows 可以用安装包，装完重开终端。

```bash
go version
go env GOROOT GOPATH GOPROXY GOSUMDB GOTOOLCHAIN GO111MODULE
```

`GOROOT` 是当前这条工具链的安装目录，里面有标准库源码。不要把业务代码放进去。

`GOPATH` 现在主要放模块缓存（`pkg/mod`）和 `go install` 装的二进制（`bin`）。从 Go 1.16 起，在含有 `go.mod` 的目录里默认就是模块模式。`GO111MODULE` 的默认行为已经是开。新代码不要再按 `GOPATH/src/导入路径` 的旧布局摆放。

## 代理和校验

`GOPROXY` 的默认值是 `https://proxy.golang.org,direct`。列表从左到右试。`direct` 表示代理失败后直接找版本控制服务器。

`GOSUMDB` 默认是 `sum.golang.org`。它核对下载到的模块和公开的校验和是否一致，用来发现镜像被换包。私有模块走不了公共校验库时，把它们的路径前缀写进 `GOPRIVATE`（或 `GONOSUMDB`）。公开模块不要关掉校验。

连不上官方代理时，可以改用户配置，例如：

```bash
go env -w GOPROXY=https://goproxy.cn,direct
```

`go env -w` 写的是这台机器用户目录里的配置，不是仓库文件。换一台机器不会跟着仓库走。团队要统一代理时，写在文档或 CI 的环境变量里，不要提交进 `go.mod`。

## 工具链版本

本仓库 `go.mod` 有一行 `go 1.27.1`。在仓库根目录执行命令时，`GOTOOLCHAIN=auto` 会按这一行选择 Go 1.27.1，哪怕你系统里的 `go` 命令更旧。工具链不够时，`go` 命令会下载对应版本。

`GOTOOLCHAIN=local` 表示只用本机已安装的工具链，不自动下载。CI 里如果禁止外网下载工具链，就要事先装好 1.27.1，或者把 `GOTOOLCHAIN` 指到已缓存的版本。

在仓库根目录执行 `go env GOVERSION`，应当看到 `go1.27.1`。在仓库外的空目录里，看到的是系统自己的 `go version`。两处不一致是正常的。

## 第一个程序

[examples/a1hello/main.go](../../../examples/a1hello/main.go)：

```go
package main

import "fmt"

func main() {
    fmt.Println("你好，Go")
}
```

```bash
go run ./examples/a1hello
```

输出：

```text
你好，Go
```

`package main` 并且有 `func main()` 的包才能当程序入口。`main` 函数没有参数，也没有返回值。程序的退出码用 `os.Exit`，正常结束就是 0。

`go run` 会编译并执行，二进制放在临时目录。`go build -o hello ./examples/a1hello` 把可执行文件留在当前目录。`go install` 把二进制装到 `GOBIN`，没设置时是 `GOPATH/bin`。库包不要 `go install` 到 PATH 里，它没有 `main`。

编译过程可以分成：`go` 命令解析 `go.mod` 和构建列表，编译器做词法、类型检查和优化，汇编器产生目标文件，链接器拼成可执行文件。你平时不需要分步调用 `compile` 和 `link`。要看编译器为什么把变量放到堆上，用 `go build -gcflags=-m`，见 [内存与逃逸](../运行时/C1-内存与逃逸.md)。

## 编辑器和格式化

装语言服务器 `gopls`。保存时格式化。VS Code 的 Go 插件和 GoLand 都能做这件事。

`gofmt` 没有风格开关，团队不讨论花括号放哪。格式化请用 `go fmt`。它走 `go.mod` 指定的工具链。系统里如果还留着旧的 `gofmt`，它不认识 Go 1.27 的泛型方法，会直接报语法错误。

## 对比陷阱

| 做法 | 结果 |
| --- | --- |
| 把源码放进 `GOPATH/src`，目录里又没有 `go.mod` | 回到旧的 GOPATH 查找规则，导入路径和本教程对不上 |
| 用系统旧 `gofmt` 格式化含泛型方法的文件 | 报 “method must have no type parameters” 一类语法错误 |
| 把 `go env -w` 的结果提交进仓库 | 那是本机配置，别人的机器不会读这个文件 |
| 在仓库外复制了第 6 章以后标了 Go 1.27 的代码 | 泛型方法和提升字段字面量键会编译失败。跟着本仓库的 `go.mod` |
| 把某次 `go test -bench` 的纳秒数写进文档当标准答案 | 数字跟机器有关。main 上有一批这样的实测数字，本教程不引用它们 |

## 练习

1. 把打印的字符串改成你的名字，再 `go run` 一次。
2. 在仓库根目录和仓库外各执行一次 `go env GOVERSION`，记下两个结果差在哪。
3. 执行 `go env GOPROXY GOSUMDB`，说出这两个变量各防的是什么问题。

## 面试延伸

面试官问「你们项目的 Go 版本由谁决定」时，答案是 `go.mod` 的 `go` 行加上 `GOTOOLCHAIN`。本机 `go version` 更旧时，`auto` 仍会按模块声明的版本编译。问「依赖从哪下载、怎么防篡改」时，分开说 `GOPROXY` 和 `GOSUMDB`。私有模块用 `GOPRIVATE` 跳过公共校验库，公开模块保持校验。

## 问答题

### 问：`go run` 和 `go build` 差在哪？

`go run ./examples/a1hello` 编译到临时目录并立刻执行，结束之后那个二进制不留在仓库里。`go build -o hello ./examples/a1hello` 把可执行文件留在你指定的位置。两者用的是同一套编译规则，差别是产物放哪、要不要马上执行。库包没有 `main`，不能 `go run`。

### 问：`GOROOT` 和 `GOPATH` 现在还要设吗？

官方安装会自己知道 `GOROOT`。不要把业务代码放进 `GOROOT`。`GOPATH` 默认在用户目录，模块缓存和 `go install` 的二进制放在那里。新项目在含有 `go.mod` 的目录里工作，不再把源码摆到 `GOPATH/src`。

### 问：`GOPROXY` 写成一串地址是什么意思？

从左到右试。`https://proxy.golang.org,direct` 先问官方代理，失败再用 `direct` 去版本控制服务器。公司代理写在前面，最后留一个 `direct` 作为退路。`go env -w` 只改这台机器的用户配置。

### 问：关掉 `GOSUMDB` 会怎样？

公开模块失去「代理上的字节和公开校验库是否一致」这一层核对。私有模块走不了公共校验库，应当放进 `GOPRIVATE`，而不是把校验整个关掉。`go.sum` 仍要提交，它记录的是你这台构建曾经见过的哈希。

### 问：为什么仓库里 `go env GOVERSION` 和系统 `go version` 可以不同？

`GOTOOLCHAIN=auto` 按 `go.mod` 的 `go 1.27.1` 选择工具链。仓库外没有这份 `go.mod`，用的是系统安装的 `go`。在仓库根目录编译，才是本教程锁定的版本。

### 问：`go fmt` 和系统里的 `gofmt` 为什么不能混用？

`go fmt` 调用模块要求的工具链。旧的 `gofmt` 不认识 Go 1.27 的泛型方法，会把正确的源码报成语法错误。编辑器里把格式化命令指到 `go fmt`。

### 问：第一个程序最少要有什么？

`package main` 和一个 `func main()`。`main` 没有参数和返回值。本教程的示例打印 `你好，Go`。退出码在正常返回时是 0，要非 0 用 `os.Exit`。

### 问：编译器、汇编器、链接器需要自己调用吗？

不需要。`go build` 会解析模块、编译、汇编、链接。要看变量有没有逃到堆上，再加 `-gcflags=-m`，见 [内存与逃逸](../运行时/C1-内存与逃逸.md)。不要把某次构建的耗时写成标准。
