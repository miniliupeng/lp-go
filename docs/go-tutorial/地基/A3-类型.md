## 这一章你要会什么

分清数组和切片、字节和码点、nil map 和空 map，会用三下标切片和 `copy`，知道哪些转换必须写出来。

## 基本类型和转换

常用的有 `bool`、`int`、`int64`、`uint64`、`float64`、`string`、`byte`、`rune`。`byte` 是 `uint8` 的别名。`rune` 是 `int32` 的别名，表示一个 Unicode 码点。`int` 的宽度跟平台有关。协议字段、数据库计数、原子变量写 `int32` 或 `int64`，不要用裸 `int` 跨机器传。

不同类型不能直接运算，必须显式转换。`int` 和 `int64` 相加之前要先转成同一个类型。转换可能截断，编译器不会替你检查数值还在不在范围内。

`string(rune(65))` 是 `"A"`，因为 U+0041 是 A。`string(65)` 得到的也是这个码点，不是十进制文本 `"65"`。十进制文本用 `strconv.Itoa` 或 `strconv.FormatInt`。`go vet` 的 `stringintconv` 会提醒把整数直接转成字符串。

## 字符串、字节、码点

字符串是不可变的字节序列，通常按 UTF-8 解释。`len("中")` 是 3，`len([]rune("中"))` 是 1。下标 `s[i]` 是一个字节，类型是 `byte`。`for i, r := range s` 时，`i` 是字节下标，`r` 是 `rune`，一个码点可能让下标一次跳 1、2、3 或 4。

切字符串切的是字节。切在码点中间会得到一段不完整的 UTF-8。按字符截取要先转成 `[]rune`，或用 `utf8` 包找到边界。

字符串不能按下标赋值。要改内容，转成 `[]byte`，改完再转回字符串。这一步会复制。

## 数组和切片

数组长度是类型的一部分。`[3]int` 和 `[4]int` 是不同类型，不能互相赋值。数组赋值会复制全部元素。

切片是一个小的描述符：指向底层数组的指针、长度、容量。赋值切片只复制这三个字段，不复制元素。两个切片可以共享同一块底层数组。

```go
base := make([]int, 3, 4) // len 3, cap 4
view := base[:2]
base = append(base, 9)    // 容量还够，写进原数组
```

测试锁住了：这次 `append` 之后，`view` 和 `base` 的第一个元素地址相同。容量不够时，`append` 才分配新数组，旧切片看不见新元素。

三下标 `base[low:high:max]` 的长度是 `high-low`，容量是 `max-low`。`max` 不能超过原切片的容量。用它限制后续 `append` 能碰到的范围，避免一个函数把调用方还要使用的后半段覆盖掉。测试里 `[]int{1,2,3,4,5}[1:3:4]` 的长度是 2、容量是 3。

`copy(dst, src)` 复制的个数是两个长度的较小值，返回实际复制的个数。它不会为了源更长而把目标变长。

nil 切片的长度和容量都是 0，和 nil 比较为真。`append(nil, 1)` 合法，会分配底层数组。空切片 `[]int{}` 或 `make([]int, 0)` 长度也是 0，但和 nil 比较为假。`slices.Equal` 把 nil 和空切片看成相等。`encoding/json`（v1）里，nil 切片编码成 `null`，空切片编码成 `[]`。要区分这两种时，不要用 `slices.Equal`。

`make([]int, len, cap)` 创建切片。`new(T)` 分配 `T` 并返回 `*T`，内容是零值。切片、map、channel 用 `make`，因为它们除了一块内存，还要有运行时里的内部结构。`new([]int)` 得到的是指向 nil 切片的指针，不是一条有长度的切片。

## map

```go
v, ok := m["missing"] // 没有这个键时 v 是零值，ok 是 false
```

用 `ok` 区分「没有键」和「值就是零值」。`delete(m, k)` 删掉键。键不存在时 `delete` 什么也不做，包括对 nil map 调用 `delete` 也不会 panic。向 nil map 写入会 panic。读取 nil map 得到零值。

`for range` 遍历 map 的顺序是随机的。语言故意不保证顺序，防止程序依赖某一次的桶顺序。不要靠遍历顺序做输出、签名或测试断言。需要稳定顺序时，把键取出来排序。

两个 goroutine 同时读写同一个 map，只要有一个在写，就会 panic。并发用锁，或者确认访问模式符合 `sync.Map` 的两种场景，见 [同步与原子](../运行时/C5-同步与原子.md)。

Go 1.27.1 的 map 实现在 `internal/runtime/maps`。文件头写明设计基于 Swiss Table：8 个槽为一组，控制字里放每个槽的状态和哈希的低 7 位（H2），高 57 位（H1）用来探测。这是实现。语言层面它仍是哈希表，遍历仍无序，并发写仍 panic。

## 指针

`p := &x` 取地址，`*p` 解引用。没有指针运算，不能 `p+1` 走到下一个元素。零值指针是 nil，对 nil 解引用会 panic。

参数传递永远复制值。复制指针只复制地址，所以函数可以通过指针改到调用方的变量。复制切片头不会复制底层数组，所以函数里对元素的修改，调用方看得见；函数里 `append` 如果触发了扩容，调用方的切片头不变，看不见新长度。

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| `len` 对所有字符串返回字符数 | 返回字节数 |
| `append` 之后别的切片一定不变 | 容量够时会改同一块底层数组 |
| 背一个永远成立的扩容倍数 | 运行时公式还会按大小类取整，见 C1 |
| nil 切片不能 `append` | 可以，`append` 会分配 |
| 遍历 map 的顺序是插入顺序 | 顺序随机 |
| `sync.Map` 在所有场景都更快 | 文档说大多数代码应该用普通 map 加锁 |

## 问答题

### 问：数组和切片在类型系统里差在哪？

数组长度是类型的一部分，`[3]int` 和 `[4]int` 不能互相赋值，赋值会复制全部元素。切片是指向底层数组的指针加上长度和容量，赋值只复制这三个字段。

### 问：`make([]int, 3, 4)` 之后 `append` 一个元素，别的切片看不看得到？

容量还够，写进原来的数组。`TestAppendSharesBackingArray` 把 `base[:2]` 和扩容前的 `base` 放在一起，断言第一个元素的地址相同。容量不够时才换新数组，旧切片头不变。

### 问：三下标切出来的容量是多少？

`base[1:3:4]` 的长度是 `3-1 = 2`，容量是 `4-1 = 3`。`max` 不能超过原容量。把切片交给别的函数之前加上第三个下标，对方的 `append` 就不会碰到你还要用的后半段。

### 问：`copy` 会把目标变长吗？

不会。复制个数是两个长度的较小值。测试里目标长度是 2，源有 3 个元素，复制 2 个，目标变成 `9, 8`。

### 问：nil 切片和空切片怎么选？

两者长度都是 0。nil 和 nil 比较为真，空切片不是 nil。`append(nil, 1)` 合法。`slices.Equal` 把它们看成相等。`encoding/json` 把 nil 编成 `null`，把空切片编成 `[]`。要保留这个差别时不要用 `slices.Equal`。

### 问：`new` 和 `make` 各分配什么？

`new(T)` 返回 `*T`，内容是零值。`new([]int)` 是指向 nil 切片的指针。切片、map、channel 用 `make`，因为除了一块内存还要有运行时的内部结构。

### 问：map 的实现换成 Swiss Table 之后，语言规则变了吗？

没有。Go 1.27.1 的 `internal/runtime/maps` 用 8 个槽一组、控制字里放哈希低 7 位。遍历仍然无序，并发写仍然 panic，读取缺失键仍然是零值加 `ok == false`。

### 问：为什么没有指针运算？

`p+1` 不是走到下一个元素的写法。要下一个元素用切片或数组下标。nil 指针解引用会 panic。函数参数是副本，改指针指向的对象，调用方看得见；改指针变量本身，调用方的指针不变。
