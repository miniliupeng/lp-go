# A5 函数、结构体与方法

示例在 [examples/a5struct](../../../examples/a5struct/task.go)。这一章把参数怎么传、`defer` 什么时候求值、方法集差在哪讲完。接口值不再自动取地址的部分在 [接口](A6-接口.md)。

## 这一章你要会什么

会写多返回值和可变参数，说清闭包捕获的是变量，能预测 `defer` 的顺序和参数求值时机，能用命名返回值接住 `recover`，能区分值接收者和指针接收者。

## 参数是值的副本

函数参数永远是一份副本。传入 `int`，函数里改形参，调用方的变量不变。传入指针，复制的是地址，函数可以通过指针改到调用方的变量。传入切片，复制的是切片头：长度、容量和底层数组指针。函数改元素，调用方看得见；函数里的 `append` 如果换了新数组，调用方的切片头还是旧的。

这和「传引用」不是同一套说法。Go 没有引用参数。看起来像共享，是因为复制的那个值本身是指针或切片头。

## 多返回值、命名结果、可变参数

失败用额外的返回值表示，习惯上最后一个是 `error`。`Div(7, 2)` 得到商 3、余数 1、错误 nil。除数是 0 时返回 `divide by zero`，不 panic。整数除法向零截断，所以商是 3。

可以给结果起名字：

```go
func Div(a, b int) (q, r int, err error)
```

命名结果在函数开头就是零值。`return` 不带表达式时，返回这些名字的当前值，称为裸返回。函数稍长时，裸返回让读者去函数顶部找名字，读起来费劲。短函数里用来少写一遍可以。`defer` 要改写调用方最终看到的结果时，命名结果是正当用途，见下面的 `DeferOrder`。

`Sum(nums ...int)` 在函数内部就是 `[]int`。已有切片时用 `Sum(s...)`。可变参数必须是最后一个参数。调用时不传，函数里拿到的是 nil 切片，`range` 零次，结果是 0。

相同类型的连续参数可以写成 `func f(a, b int)`。返回值类型不同就要逐个写。

## 闭包

闭包捕获的是变量本身，不是调用那一刻的拷贝，除非你把值当成参数传进去。`Counter()` 每次调用加 1，连续两次得到 1 和 2。两个闭包如果抓住同一个变量，改动互相看得见。

Go 1.22 起，`for` 的循环变量每次迭代是新变量，所以在循环里启动的闭包看到的是当次的值。见 [控制流](A4-控制流.md)。

## defer

`defer` 把调用推迟到当前函数返回前，包括正常 `return` 和 panic。多个 `defer` 后进先出。

参数在执行到 `defer` 这一行时求值，不是等到函数返回时再求值。`DeferArg` 在 `n == 1` 时把 `n` 传进 defer，随后把 `n` 改成 2。调用方看到的切片是 `[1]`。闭包如果直接读 `n`，读到的才是返回前的 2。要哪一种，就写成哪一种。

`DeferOrder` 使用命名返回值。`return out` 先把当前的切片头赋给结果，然后才跑 defer。defer 里对命名结果 `out` 再 `append`，调用方看得见，所以结果是 `body`、`defer 2`、`defer 1`。如果返回的是一个普通局部切片，defer 在 `return` 复制切片头之后才 append，调用方就看不见后面的元素。

## panic 与 recover

`panic` 停掉当前函数，先按后进先出执行 defer，再沿着调用栈往上。库函数的普通失败用 `error` 返回，见 [错误](A7-错误.md)。`panic` 留给「再继续就会把状态弄坏」的故障，例如并发写 map 时运行时自己抛出的 panic。

`recover` 只在 defer 的函数里**直接**调用时，才能接住当前 goroutine 的 panic，并返回传给 `panic` 的值。在 defer 调用的另一个函数里再调用 `recover`，接不住。没有 panic 时 `recover` 返回 nil。

`Recovered` 在 defer 里把接住的值写进命名结果，调用方得到 `"boom"`。panic 被接住之后，函数正常返回，外层看不到这次 panic。别的 goroutine 的 panic 接不住。`recover` 之后如果资源已经写了一半，要在同一个 defer 里把状态补完，不能假装什么都没发生。

## 结构体、嵌入、方法

结构体的字段按声明顺序存放。全部字段都可比较时，结构体可以用 `==`。含切片、map 或函数字段时不能比较。

`Task` 嵌入 `Author`，所以 `By` 被提升。`item.By` 和 `item.Author.By` 是同一个字段。外层如果自己也有 `By`，外层的字段优先，内层要用 `item.Author.By`。两个嵌入类型提升出同名字段、外层又没有这个字段时，直接写 `item.By` 会因为选择歧义而编译失败，必须写全路径。

值接收者 `Label` 拿到的是 `Task` 的副本，改字段不会影响调用方。指针接收者 `Finish` 把 `Done` 设为 true。选择的标准是：方法要改接收者，或者接收者很大、复制代价高，用指针；方法只读、接收者很小、希望值和指针都能自然放进接口，用值。同一个类型的方法集合里可以混用，但要记住方法集的差别。

方法集：

| 接收者 | `T` 的方法集 | `*T` 的方法集 |
| --- | --- | --- |
| `func (t T)` | 有 | 有 |
| `func (t *T)` | 没有 | 有 |

可寻址的值会自动取地址，所以局部变量 `item.Finish()` 能调用指针方法。放进接口之后，这条自动取地址不再发生。

Go 1.27.1 允许结构体字面量用提升字段的名字当键：`Task{By: "bea", Title: "note"}`。键必须是一个名字。`Author.By` 这种选择器不能当字面量键，编译器会报 `invalid field name`。未导出字段只能在同一个包的字面量里写。

构造函数通常叫 `New` 或 `NewXxx`，返回结构体或指针。需要在返回前填默认值、检查参数时用它。字段全是零值也能用时，调用方直接写字面量即可。

## 对比陷阱

| 写法 | 实际结果 |
| --- | --- |
| 函数里给形参 `n = 2`，指望调用方的 `n` 变成 2 | 形参是副本 |
| 以为 defer 的参数在返回时才读 | 执行到 `defer` 那一行就求值。`DeferArg` 得到 1 |
| 裸 `return` 很长的函数 | 读者要翻到函数签名才知道返回了什么 |
| 在普通函数里调用 `recover` | 返回 nil，panic 继续往上 |
| 值类型放进接口再调用指针方法 | 方法集里没有指针方法，编译失败 |
| 字面量键写成 `Author.By` | `invalid field name`。用提升名 `By` |

```bash
go test ./examples/a5struct -count=1
```

## 练习

1. 给 `Task` 加一个值接收者 `IsOpen() bool`，`Done` 为 false 时返回 true，并补一个测试。
2. 写一个 defer，闭包里直接读变量，再写一个把变量当参数传入。预测两个结果再跑。
3. 让 `Recovered` 的 panic 发生在另一个 goroutine 里，在原来的 goroutine 里 `recover`。确认接不住，测试里用 `defer` 把那个 goroutine 自己的 panic 接住，避免把 `go test` 打崩。

## 面试延伸

按这个顺序答：参数是值拷贝；切片和指针看起来能改调用方，是因为复制的是头或地址；`defer` 后进先出，参数立刻求值；命名返回值让 defer 能改到调用方看到的结果；`recover` 必须在出 panic 的那个 goroutine 的 defer 里直接调用。方法集题画一张表：`T` 只有值接收者，`*T` 两者都有，接口里的值不会再自动取地址。

## 问答题

### 问：`Div(7, 2)` 为什么商是 3？

整数除法向零截断。余数是 1，错误是 nil。除数是 0 时返回 `divide by zero`，不 panic。三个返回值里最后一个是 `error`，这是习惯，不是语法强制，但全仓库都按这个习惯写。

### 问：可变参数在函数里是什么类型？

`Sum(nums ...int)` 里 `nums` 的类型是 `[]int`。已有切片用 `Sum(s...)` 展开。一个都不传时是 nil 切片，`range` 零次，和是 0。可变参数必须是最后一个。

### 问：闭包捕获的是值还是变量？

是变量。`Counter` 每次调用都改同一个 `n`，所以连续两次得到 1 和 2。想要调用那一刻的副本，把值当参数传进函数。Go 1.22 起循环变量每次迭代一份，闭包看到的是当次的那一份。

### 问：`DeferArg` 为什么得到 1 而不是 2？

`defer func(v int) { ... }(n)` 的参数在执行到这一行时求值，当时 `n` 是 1。后面把 `n` 改成 2，传进去的 `v` 不变。闭包如果直接读 `n`，读到的才是返回前的值。

### 问：`DeferOrder` 为什么调用方能看见 defer 追加的元素？

结果是命名返回值。`return` 先把切片头赋给结果，然后才跑 defer。defer 再对这个命名结果 `append`，调用方看到 `body`、`defer 2`、`defer 1`。普通局部切片在 `return` 时已经把切片头复制走了，之后的 `append` 调用方看不见。

### 问：`Recovered` 为什么返回 `"boom"` 而不是把测试打崩？

panic 发生在当前 goroutine。defer 里直接调用 `recover`，把值写进命名结果。在 defer 所调用的另一层函数里 `recover`，接不住。别的 goroutine 里的 panic 也接不住。

### 问：`Task{By: "bea"}` 为什么合法？

Go 1.27.1 允许字面量键使用提升字段的名字。`By` 来自嵌入的 `Author`。键必须是名字，`Author.By` 这种选择器会报 `invalid field name`。`item.By` 和 `item.Author.By` 是同一个字段。

### 问：值接收者和指针接收者怎么选？

要改接收者，或接收者很大，用指针。只读并且希望值和指针都能放进接口，用值。`T` 的方法集只有值接收者，`*T` 两者都有。局部变量可以自动取地址，放进接口之后不会。
