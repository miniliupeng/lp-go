# A6 接口

接口是一组方法。类型实现了这些方法，就实现了接口，不用写 `implements`。示例在 [examples/a6iface](../../../examples/a6iface/speak.go)。运行时怎么摆这两个字，在 [接口、反射与剖析](../运行时/C6-接口反射与剖析.md)。

## 这一章你要会什么

会设计小接口，判断一个类型能不能放进接口，区分 nil 接口和带类型的 nil 指针，会用类型断言和类型 switch。

## 小接口

标准库把接口拆得很小。`io.Reader` 只有 `Read`，`io.Writer` 只有 `Write`，`io.Closer` 只有 `Close`。需要两样时用组合：

```go
type ReadCloser interface {
    io.Reader
    io.Closer
}
```

函数参数写成它真正调用的那几个方法。参数写成 `interface{}` 或 `any`，调用方看不出要满足什么，函数体内只好再做类型断言。容器和算法如果只是「对很多类型做同一件事」，优先考虑 [泛型](../能写服务/B5-泛型与迭代器.md)，而不是 `any`。

接口由使用方声明，也可以由实现方所在的包声明。把接口放在使用它的包里，实现就可以留在别的包，测试时换一个假的实现，不必改实现方。

## 隐式实现与方法集

`Dog` 有值接收者 `Speak`，所以 `Dog` 和 `*Dog` 都能放进 `Speaker`。`Announce(Dog{Name: "ada"})` 得到 `ada says woof`。

`*locked` 才有 `Read`。值 `locked` 的方法集里没有这个方法，不能赋给 `io.Reader`。可寻址的局部变量 `n.Read` 会自动取地址；放进接口之后，接口里保存的是值的副本，不会再自动取地址。所以指针方法要先取地址再放进接口：`var r io.Reader = &n`。

方法集表在 [函数、结构体与方法](A5-函数结构体与方法.md)。这里多记一条：接口值里面的具体值，即使原来是可寻址的变量，放进去之后也不再可寻址。

## 接口值的两半

接口值有动态类型和动态值。空接口 `any` 在运行时是 `eface`：类型指针加数据指针。带方法的接口是 `iface`：`itab` 加数据指针。`itab` 里有接口类型、具体类型、类型哈希，以及一张方法表。这是 Go 1.27.1 编译器写 `itab` 时的布局，字段名以源码为准，不要当成语言规范里的名字。

两半都是空，接口才等于 nil。下面这个 `r` 不是 nil 接口：

```go
var p *locked
var r io.Reader = p
```

动态类型是 `*locked`，动态值是 nil。`r == nil` 为 false。对它 `Read` 会进到指针接收者，示例返回错误 `nil reader`。

函数要表示失败时，返回一个没有动态类型的 nil 错误：

```go
func load() error {
    var p *locked
    if p == nil {
        return nil // nil 接口
    }
    return p
}
```

`return p` 在 `p == nil` 时，调用方的 `err == nil` 仍是 false。这是接口题里最常见的坑。

## 类型断言和类型 switch

从接口里取回具体类型：

```go
d, ok := s.(Dog) // ok 为 false 时不 panic，d 是零值
d = s.(Dog)      // 失败时 panic
```

类型 switch 按动态类型分支，失败走 `default`，不会 panic：

```go
switch v := s.(type) {
case Dog:
    use(v.Name)
case *Dog:
    use(v.Name)
default:
}
```

`v` 在每个分支里的类型就是那个 case。类型 switch 里不能写 `fallthrough`。

断言只看动态类型，不看你心里觉得它「应该是」什么。`*Dog` 和 `Dog` 是不同类型，两个 case 都要写，或者断言之前先决定放进去的是哪一个。

## 对比陷阱

| 写法 | 实际结果 |
| --- | --- |
| 以为实现接口要写 `implements` | 方法集对上就实现了 |
| `var p *T; var err error = p` 然后判断 `err == nil` | 为 false。类型是 `*T`，值是 nil |
| 把值放进接口再调指针方法 | 编译失败。先取地址 |
| 用不带 `ok` 的断言处理外部输入 | 类型不对就 panic。外部输入用 `ok` 或类型 switch |
| 参数写成 `any` 再在里面断言出三种类型 | 调用方失去编译期检查。改成小接口或类型参数 |

## 运行

```bash
go test ./examples/a6iface -count=1
```

## 练习

1. 给 `Dog` 再写一个 `Cat`，用同一个 `Announce` 打印猫的叫声。不要改 `Announce` 的参数类型。
2. 写一个函数返回 `error`。内部构造一个 nil 的 `*FieldError`（见 [错误](A7-错误.md)），比较 `return nil` 和 `return fe` 两种写法下调用方的 `err == nil`。
3. 用类型 switch 同时处理 `Dog` 和 `*Dog`，确认漏掉指针那一支时断言进不了值那一支。

## 面试延伸

先说接口值有类型和值两半，两半都空才是 nil。再举 typed nil：把 nil 指针放进 `error`，`== nil` 为 false，方法调用会进到具体类型的指针接收者。然后说方法集：值接收者两边都有，指针接收者只有 `*T` 有，接口里不会自动取地址。最后说小接口和组合，`io.ReadCloser` 这种嵌入是方法集合并，不是结构体嵌入。

## 问答题

### 问：实现接口要写 `implements` 吗？

不用。方法集对上就实现了。`Dog` 有值接收者 `Speak`，值和指针都能放进 `Speaker`。`Announce(Dog{Name: "ada"})` 得到 `ada says woof`。

### 问：为什么 `locked` 的值不能赋给 `io.Reader`？

`Read` 的接收者是 `*locked`。值的方法集里没有它。可寻址的局部变量调用 `n.Read` 时编译器会取地址；放进接口的是副本，不会再取地址。指针方法要先写成 `&n` 再放进去。

### 问：typed nil 和 nil 接口怎么区分？

`var p *locked; var r io.Reader = p` 之后，`r == nil` 为 false。动态类型是 `*locked`，动态值是 nil。对它调用 `Read` 会进到指针方法，示例返回 `nil reader`。表示「没有错误」时 `return nil`，不要 `return p`。

### 问：`eface` 和 `iface` 各是什么？

`any` 是 `eface`：类型指针加数据指针。带方法的接口是 `iface`：`itab` 加数据指针。`itab` 里有接口类型、具体类型、类型哈希和方法表。布局以 Go 1.27.1 源码为准，见 [接口、反射与剖析](../运行时/C6-接口反射与剖析.md)。

### 问：类型断言的两种写法怎么选？

`v, ok := x.(T)` 失败时 `ok` 为 false，不 panic。`x.(T)` 失败时 panic。外部输入用带 `ok` 的形式或类型 switch。`*Dog` 和 `Dog` 是不同类型，两个 case 都要写。类型 switch 不能 `fallthrough`。

### 问：接口组合和结构体嵌入一样吗？

不一样。`io.ReadCloser` 嵌入 `Reader` 和 `Closer`，得到的是方法的并集。这里没有字段，也没有提升字段的数据。结构体嵌入提升的是字段和方法。

### 问：参数写成 `any` 再在里面断言，问题在哪？

调用方失去编译期检查，函数能接受任何东西，错误要到运行才出现。能用小接口说清的行为，用小接口。只是容器要换元素类型，用类型参数，见 [泛型与迭代器](../能写服务/B5-泛型与迭代器.md)。

### 问：接口值里的具体值还能取地址吗？

不能。放进接口时复制了一份。这份副本不可寻址，所以指针方法必须在放进去之前就由指针持有。反射里 `CanSet` 为 false 是同一件事的另一面。
