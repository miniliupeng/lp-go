# A7 错误

`error` 是一个接口：`Error() string`。普通失败返回 `error`，调用方决定怎么处理。示例在 [examples/a7err](../../../examples/a7err/check.go)。panic 和 `recover` 的调用规则在 [函数、结构体与方法](A5-函数结构体与方法.md)。

## 这一章你要会什么

会选哨兵、错误类型或包装这三种里的一种，会用 `errors.Is`、`errors.As` 和 `errors.Join`，知道 `%w` 和 `%v` 的差别，以及 Go 1.27 的 printf 检查在防什么。

## 什么时候返回错误

库函数遇到「调用方可以理解并决定下一步」的情况，返回 `error`。包括解析失败、没找到、校验不通过、对端关闭。

`panic` 留给不变量已经被破坏的情况。运行时对 nil 指针解引用、向已关闭的 channel 发送、并发写 map，都会 panic。业务代码里主动 `panic` 表示「这里再往下跑没有意义」。HTTP 处理器里用 `recover` 兜一层，是为了把一条请求的 panic 变成 500，而不是让整个进程退出。兜住之后要记日志，把现场留住。

不要用 panic 代替「用户把年龄填成字母」。那是 `ParseAge` 这种返回值。

## 三种错误

**哨兵**是包级变量，用 `errors.Is` 比较。`ErrEmpty` 是哨兵。`ParseAge("")` 返回它。`Is` 会沿着 `Unwrap() error` 或 `Unwrap() []error` 往下找，找到同一条哨兵就返回 true。哨兵适合调用方必须分支的少数情况：空输入、`io.EOF`、`sql.ErrNoRows`。哨兵变成公共 API 之后就不能改它的字符串含义，调用方可能已经在比较它。

**错误类型**带字段。`ParseAge("4a")` 返回 `*FieldError`，里面有字段名和原因。`errors.As` 把这条链里第一个能放进目标类型的错误取出来。目标必须是指针。这里 `fe` 的类型是 `*FieldError`，传给 `As` 的是 `&fe`，类型是 `**FieldError`。取出来之后读 `fe.Field`，不要去解析 `Error()` 拼出来的句子。

**包装**在外层加上动作，内层仍能被找到：

```go
fmt.Errorf("parse age: %w", err)
```

`%w` 让返回值实现 `Unwrap`。`%v` 只是把文本拼进去，`Is` 和 `As` 都穿不透。日志里想隐藏内部错误时用 `%v`。需要调用方判断时用 `%w`。一层只包一个 `%w`。

## Join

`errors.Join` 把多个错误收成一个。`Together(ErrEmpty, ...)` 之后 `errors.Is` 仍能找到 `ErrEmpty`。某一个是 nil 时 `Join` 会丢掉它。全是 nil 时结果是 nil。适合一次校验收集多条字段错误，或者 `defer` 里关闭文件时把关闭错误和原来的错误放在一起返回。

关闭文件的惯用写法依赖命名返回值：

```go
func read() (err error) {
    f, err := os.Open(name)
    if err != nil {
        return err
    }
    defer func() {
        err = errors.Join(err, f.Close())
    }()
    // 读 f，失败时 return err
    return nil
}
```

## Go 1.27 的 printf 检查

包装时传实现了 `error` 的值。Go 1.27 的 printf 分析器会报告一种写错的包装：`%w` 的参数是 `*E`，而 `E` 自己实现了 `error`。诊断文本写的是这会破坏 `errors.Is`。原因是指针和值的方法集、具体动态类型会和 `Is` 想找的那个类型错开。包装时传 `E` 的值，或者让指针类型不要和值类型同时充当同一种错误。

## 不要比较错误字符串

`err.Error() == "eof"` 会在对方改了标点、加了包装文本之后失效。包装后的 `Error()` 通常含有冒号和前后文，和哨兵的原文不相等。判断用 `errors.Is`。取字段用 `errors.As`。把 `Error()` 的句子展示给用户或写进日志可以，用它做分支不行。

HTTP 里把 `err.Error()` 原样写进响应体，可能把内部路径和 SQL 漏给调用方。对用户返回固定的短句，细节留给日志。见 [HTTP 服务](../能写服务/B3-HTTP服务.md)。

## 对比陷阱

| 写法 | 实际结果 |
| --- | --- |
| `err.Error()` 和字符串比较 | 包装一层就对不上 |
| 用 `%v` 以为 `errors.Is` 还能找到内层 | `%v` 不实现 `Unwrap` |
| `As` 的目标传了值而不是指针 | 编译失败或匹配不上。目标是指向具体错误类型的指针 |
| `return (*FieldError)(nil)` | 调用方 `err == nil` 为 false。见 [接口](A6-接口.md) |
| `Join` 里夹了一个 nil | nil 被丢掉。全是 nil 时整个结果是 nil |
| 用 panic 报告校验失败 | 调用方只能 `recover`，签名上看不出失败 |

2. 把同一个错误分别用 `%w` 和 `%v` 包一层，对两份结果调用 `errors.Is`，确认只有 `%w` 为 true。

## 面试延伸

先给原则：普通失败返回 `error`，`panic` 留给不变量被破坏。再讲三种：哨兵配合 `Is`，类型配合 `As`，`%w` 保留链条，`%v` 切断链条。`Join` 用于多错误，nil 项会被丢掉。typed nil 要主动提：返回 nil 指针会使 `err == nil` 失败。Go 1.27 的 `%w` 检查提到「`*E` 且 `E` 实现了 `error`」这一句即可。

## 问答题

### 问：`ParseAge("")` 和 `ParseAge("4a")` 分别返回什么？

空字符串返回哨兵 `ErrEmpty`，调用方用 `errors.Is`。`"4a"` 返回 `*FieldError`，调用方用 `errors.As` 取出字段名。目标是 `&fe`，`fe` 的类型是 `*FieldError`。

### 问：`%w` 和 `%v` 怎么选？

`%w` 让外层实现 `Unwrap`，`Is` 和 `As` 还能找到内层。`%v` 只拼接文本，链条断开。需要调用方分支时用 `%w`。只想写进日志、不想让对方依赖内部错误时用 `%v`。一层一个 `%w`。

### 问：为什么不要比较 `err.Error()`？

包装之后句子里有冒号和前后文，和哨兵原文不相等。对方改了标点也会失效。分支用 `Is` 和 `As`。HTTP 响应里更不要把 `Error()` 原样回给用户。

### 问：`errors.Join` 怎么处理 nil？

nil 项被丢掉。全是 nil 时结果是 nil。适合一次校验收集多条错误，也适合 `defer` 里把 `Close` 的错误并进命名返回值。

### 问：Go 1.27 的 printf 检查在防什么？

`%w` 的操作数如果是 `*E`，而 `E` 自己实现了 `error`，分析器报告这会破坏 `errors.Is`。包装时传值类型的错误，不要让值和指针同时充当同一种错误。

### 问：什么时候允许 panic？

不变量已经破了，例如运行时发现并发写 map、向已关闭的 channel 发送。用户把年龄写成字母是返回值，不是 panic。HTTP 里 `recover` 可以把一条请求变成 500，兜住之后要记日志。

### 问：返回 `(*FieldError)(nil)` 会怎样？

调用方的 `err == nil` 为 false。动态类型是 `*FieldError`，动态值是 nil。没有错误时返回不带类型的 nil。见 [接口](A6-接口.md)。

### 问：哨兵适合公开成 API 吗？

适合调用方必须分支的少数情况，例如 `io.EOF`、`sql.ErrNoRows`、本包的 `ErrEmpty`。一旦公开，字符串的含义就不能随便改，因为有人可能在比较这个变量本身。更多细节用错误类型带字段。
