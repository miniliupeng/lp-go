# A8 包与模块

一个目录一个包。包名通常等于目录名。其他包只能使用大写开头的名字。`mathx.Add` 和 `mathx.Clamp` 在 [examples/a8calc/mathx](../../../examples/a8calc/mathx/mathx.go)。工具链、代理和校验在 [环境与第一个程序](A1-环境与第一个程序.md)。

## 这一章你要会什么

会划分包和 `internal`，读懂 `go.mod` 与 `go.sum`，说清最小版本选择，知道 `replace` 只对主模块生效，能预测包的初始化顺序。

## 包和导出

包是编译和可见性的单位。小写名字只在本包可见，测试文件如果用 `package mathx` 也算本包，能看见小写名字。`package mathx_test` 是外部测试包，只能走导出 API。外部测试包用来确认你导出的就是调用方能用的那部分。

导入路径是「模块路径 + 目录」。本仓库的 `go.mod` 是：

```text
module tutorial

go 1.27.1
```

所以 main 写成 `import "tutorial/examples/a8calc/mathx"`。导入名默认是包名，不是目录名。两者不一致时，调用用的是包名。可以用 `import m "tutorial/examples/a8calc/mathx"` 换一个本地名字。点导入 `import . "pkg"` 会把名字倒进当前文件，新代码不用。

导入了却不用，编译失败。只为了执行对方的 `init` 时，写成空白导入 `import _ "image/png"`。`image.Decode` 因此认识 PNG。空白导入要有注释说明为什么需要这个副作用。

`internal` 是编译器执行的可见性。导入路径里出现元素 `internal` 时，只有它的父目录这棵树能导入它。`tutorial/internal/store` 可以被 `tutorial` 下面的包导入，不能被别的模块导入。业务服务里，`cmd/server` 只留启动，能测的逻辑放进 `internal`。见 [目录与检查](../能写服务/B6-目录与检查.md)。

## go.mod 里有什么

`module` 行是别人导入你时的前缀。`go` 行是这个模块声明的语言版本。`go vet` 的 `stdversion` 从 Go 1.22 起会按这一行（或文件顶部的 `//go:build go1.X`）拒绝「对这个文件来说太新」的标准库符号。

`require` 列出依赖模块和版本。`require` 后面标 `// indirect` 的，是自己的代码没直接导入、但构建需要的模块。`go mod tidy` 会重算直接和间接。

`exclude` 让主模块拒绝某个版本。`retract` 写在模块自己的 `go.mod` 里，声明自己的某些版本不该再被别人选用。撤回要发一个更高的版本，别人才能看见这条声明。

`replace` 把一个模块换成本地目录或另一个版本。它只在**当前主模块**的构建里生效。别人把你当成依赖来构建时，你的 `go.mod` 里的 `replace` 会被忽略。所以 `replace` 可以用来改本地联调，不能用来把一个修复偷偷塞给下游。

## go.sum

`go.sum` 记录下载过的模块内容的哈希。一行对应一个模块版本的 `go.mod` 或模块 zip。构建时如果内容对不上，`go` 命令失败。它和 `GOSUMDB` 配合：代理给出的字节，还要和公开的校验库对得上。

`go.sum` 要和 `go.mod` 一起提交。它不是「把整张构建图锁死的清单」。构建图由下面的版本选择算法算出来，`go.sum` 负责那些被选中、并且下载过的内容没有被换掉。

## 最小版本选择

Go 模块用最小版本选择（MVS）。每条 `require` 表示「至少这个版本」。对图里的每一个模块，算法取所有要求里最高的那个版本。因为要求只有下限，这个最高要求就是能同时满足所有人的最低版本。

它不会自动跳到该模块的最新标签。上游发了 `v1.3.0`，你的图里最高只要求 `v1.2.0`，构建就用 `v1.2.0`。要升高，就在主模块里 `go get example.com/mod@v1.3.0`，再 `go mod tidy`。

`v2` 及以上的模块路径要带主版本后缀，例如 `example.com/mod/v2`。`v0` 和 `v1` 不带后缀。导入路径和 `module` 行必须一致。

伪版本是还没有标签的提交，形如 `v0.0.0-20240102150405-abcdef`。可以用来指向一个尚未发布的修复。长期依赖仍用发布过的标签。

## 工作区

一个仓库里有多个模块时，用 `go.work` 把它们放进同一个工作区：

```text
go 1.27.1

use (
    ./modA
    ./modB
)
```

工作区让本地的 `modA` 直接使用本地的 `modB`，不必先发布。`go.work` 是开发者机器上的视图，通常不作为「这个模块发布之后别人怎么构建」的依据。要提交还是忽略，看团队是否约定所有人都用同一份工作区。本教程只有一个模块，没有 `go.work`。

## 常用命令

| 命令 | 作用 |
| --- | --- |
| `go mod tidy` | 按源码里的导入增减 `require`，整理 `go.sum` |
| `go get example.com/mod@v1.2.3` | 把这条要求升到或降到指定版本 |
| `go get example.com/mod@none` | 去掉这条直接要求，再看 tidy 是否还需要它 |
| `go list -m all` | 打印构建图里选中的模块版本 |
| `go mod why -m example.com/mod` | 说明为什么需要这个模块 |
| `go mod vendor` | 把依赖复制到 `vendor/`。构建加 `-mod=vendor` 时用这份副本 |

本教程的示例只用标准库，没有第三方 `require`。

## 初始化顺序

被导入的包先初始化，每个包只初始化一次。包自己先按依赖给包级变量赋初值，再调用 `init`。多个文件时，构建系统按编译器拿到的文件顺序执行 `init`，这个顺序通常是文件名的字典序。不要让业务正确性依赖「`b.go` 的 `init` 一定在 `c.go` 之前」。

如果包 `p` 导入包 `q`，`q` 的初始化完成 happens before `p` 的初始化开始。循环导入编译失败。

`init` 里可以注册解码器、校验包级配置。不要在 `init` 里连接数据库、监听端口或启动停不下来的 goroutine。那些事放到 `main` 或显式的 `Run` 函数里，测试才不用导入一个包就连上外部系统。

## 运行

```bash
go test ./examples/a8calc/mathx
go run ./examples/a8calc
```

`go run` 的输出：

```text
add=8
clamp=5 err=<nil>
bad=mathx: lo 3 > hi 1
```

`Clamp(10, 0, 5)` 收到上限 5。`lo > hi` 时返回错误，不夹紧。

## 对比陷阱

| 做法 | 实际结果 |
| --- | --- |
| 只提交 `go.mod`，不提交 `go.sum` | 别人无法核对模块内容 |
| 在库模块的 `go.mod` 里写 `replace`，指望下游也换过去 | 下游构建会忽略你的 `replace` |
| 以为 `go get` 总会拉到仓库最新提交 | MVS 用的是图里被要求的版本。升高要显式 `go get` 一个版本 |
| 在 `init` 里开数据库连接 | 任何导入这个包的测试都会触发连接 |
| 依赖两个文件的 `init` 谁先跑 | 那是编译器的文件顺序，不是语言给业务的承诺 |

## 练习

1. 在 `mathx` 里加 `Sub`，写表驱动测试，再在 `main` 里打印一次。
2. 执行 `go list -m all`，确认目前只有主模块 `tutorial`。
3. 把 `image/png` 的空白导入写进一个小程序，调用 `image.Decode` 解一张 PNG。去掉空白导入，确认解码失败。不要把测试图片提交成大文件，用标准库测试里已有的做法或自己写最小的字节。

## 面试延伸

`go.mod` 是要求清单，`go.sum` 是内容哈希。版本选择是 MVS：每条要求是下限，每个模块取要求中的最高版本，也就是能满足全部下限的最低版本。`replace` 只影响主模块自己的构建。`internal` 由编译器限制导入。初始化上，被导入的包先完成，`init` 不拿来做网络和数据库。

## 问答题

### 问：导入路径用目录名还是包名？

导入路径是模块路径加目录。调用时用的是包名。两者不一致时，以 `package` 声明为准。本仓库 `mathx` 的导入路径是 `tutorial/examples/a8calc/mathx`。

### 问：`go.sum` 是锁文件吗？

它记录模块内容的哈希，用来发现字节被换掉。构建图由 MVS 从各模块的 `go.mod` 算出来，不是把 `go.sum` 当成一份固定的版本清单去解。两者都要提交。

### 问：上游发了新版本，构建会自动用上吗？

不会。图里最高只要求 `v1.2.0`，就用 `v1.2.0`。升高要在主模块 `go get example.com/mod@v1.3.0`，再 `go mod tidy`。

### 问：库模块里的 `replace` 对下游有用吗？

没有。下游把你当依赖来构建时，忽略你的 `replace`。`replace` 只适合主模块自己的本地联调。修复要发布成别人能 `require` 的版本。

### 问：`v2` 的导入路径为什么带后缀？

`v2` 及以上的模块路径要写成 `example.com/mod/v2`。`v0` 和 `v1` 不带。`module` 行和导入路径必须一致。

### 问：`internal` 谁能导入？

导入路径里出现 `internal` 时，只有它的父目录这棵树能导入。别的模块不行。这是编译器的规则，不是约定。

### 问：多个文件的 `init` 谁先执行？

被导入的包先初始化完。本包先给包级变量赋初值，再跑 `init`。文件之间的顺序通常是编译器拿到的文件名字典序。业务不要依赖 `b.go` 一定在 `c.go` 前面。

### 问：空白导入是干什么的？

`import _ "image/png"` 只为了执行对方的 `init`，让 `image.Decode` 认识 PNG。要有注释说明这个副作用。不要在 `init` 里连接数据库。

### 问：`go.work` 要提交吗？

工作区让本地多个模块互相使用未发布的代码。它是开发视图。别人把你的一个模块当依赖时，不读你的 `go.work`。本教程只有一个模块，没有工作区文件。
