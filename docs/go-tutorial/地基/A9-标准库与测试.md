# A9 标准库与测试

这一章把日常会用到的测试写法和几组标准库放在一起。JSON 的重复键、`os.Root` 在 [JSON 与文件](../能写服务/B4-JSON与文件.md)。性能采样在 [接口、反射与剖析](../运行时/C6-接口反射与剖析.md)。

## 这一章你要会什么

会写表驱动测试、`Example` 和带 `t.Helper` 的断言，知道 `b.Loop` 在量什么，会用 `flag`、`filepath`、`time` 的参考时间和 `bufio.Scanner`。

## 表驱动测试

测试文件以 `_test.go` 结尾，函数名是 `TestXxx(t *testing.T)`。`go test` 不会把它们编进普通二进制文件。

[lines_test.go](../../../examples/a9text/lines_test.go) 把输入和期望放进切片，用 `t.Run` 分子测试。`t.Fatal` 结束当前测试函数，`t.Errorf` 记录失败并继续。表里有多条断言时，用 `Errorf` 才能一次看见全部失败；前置条件不成立、后面再跑没有意义时，用 `Fatal`。

辅助函数第一行写 `t.Helper()`，报错行号会指向调用处。

`slices.Equal` 把 nil 和空切片看成相等。`NonEmptyLines("")` 返回 nil。如果必须区分 nil 和空切片，不要用它。`"a\r\n b"` 的结果是 `a` 和 `b`：`TrimSpace` 会去掉 `\r`。

`ExampleNonEmptyLines` 的输出要和 `// Output:` 注释逐字相同，包括空格和最后一行有没有换行。`go test` 会编译并运行示例。示例是给调用方看的文档，输出对不上就失败。

Go 1.22 起每次循环迭代有自己的变量，子测试里再 `t.Parallel()` 时看到的是当次的用例。并行的子测试不要写同一个没有同步的变量。并行会让测试变快，也会让顺序依赖暴露出来。

`t.Cleanup` 在该测试和它的子测试都结束后执行，后注册的先执行。Go 1.24 起 `t.Context()` 返回的 context 会在这些 Cleanup 函数被调用之前取消。用它做测试里的超时和取消，测试结束时取消会自己发生。

```bash
go test ./examples/a9text -cover
```

`-cover` 统计的是语句有没有执行到，不是分支覆盖。100% 只说明每条语句都走过，不说明每个条件的两边都走过。

## 基准和模糊测试

基准函数是 `BenchmarkXxx(b *testing.B)`。Go 1.27 的 `testing.B.Loop` 在第一次被调用时重置计时器，返回 false 时停表，这样循环前面的准备和后面的清理不算进结果。循环条件要写成 `for b.Loop()`。循环体里的调用和赋值会被保留，避免编译器把整个循环删掉。`b.N` 在循环结束后是总迭代次数，可以拿来算别的平均值。

[接口、反射与剖析](../运行时/C6-接口反射与剖析.md) 里有一个 `BenchmarkAdd`。它只说明怎么写循环。终端里打印的 `ns/op` 属于你这次运行的机器，不要写进文档当标准答案。

模糊测试函数是 `FuzzXxx(f *testing.F)`。先 `f.Add` 几份种子，再 `f.Fuzz` 给出随机输入。适合解析器：种子是合法样本和已知的坏样本，随机输入用来找崩溃和「返回了成功但结果违反不变量」。本教程的示例没有把模糊测试留在默认的 `go test ./examples/...` 里，因为模糊测试要单独跑一段时间。写解析函数时再加。

## flag

[examples/a9stdlib/main.go](../../../examples/a9stdlib/main.go)：

```bash
go run ./examples/a9stdlib -name Ada -upper
```

```text
name=Ada
- LEARN GO (done)
- WRITE TOOL (todo)
base=readme.md
when=2026-01-02T15:04:05Z
```

`flag.String` 返回指针，`Parse` 之后用 `*name`。旗标要出现在普通参数前面。`flag.Args()` 是旗标之后剩下的参数。必填项在 `Parse` 之后自己检查，`flag` 不会因为你觉得它必填就报错。

测试里不要调用会执行 `os.Exit` 的 `flag.Parse` 去解析测试进程自己的参数。库代码接受已经解析好的值，或者使用 `flag.NewFlagSet` 配上 `flag.ContinueOnError`，失败时返回错误而不是退出进程。

## JSON 与时间、路径

JSON 字段必须大写，`encoding/json` 才能看见。`json:"title"` 决定对象里的名字。`json:"title,omitempty"` 在字段为空时省略这个键。空值包括 false、0、nil 指针、nil 接口，以及长度为零的数组、切片、map 和字符串。空切片和 nil 切片都会被省略。0 和 false 如果是有意义的业务值，不要加 `omitempty`，否则对方分不清「没有」和「就是零」。

这段示例 JSON 是源码里的常量，`Unmarshal` 失败就 `panic`。解析用户输入时要返回 `error`，见 [错误](A7-错误.md)。

`path/filepath` 处理本机路径，分隔符跟操作系统走。`path` 只用斜杠，适合 URL 路径。`filepath.Base(filepath.Join("docs", "readme.md"))` 得到 `readme.md`。`Join` 会清洗路径，但用户输入里的 `..` 仍可能离开你想限定的目录。限定目录用 `os.Root`，见 B4。

`time.Format` 和 `time.Parse` 的布局参照的是参考时间 `Mon Jan 2 15:04:05 MST 2006`，也就是 2006-01-02 15:04:05。数字必须用这一组，不能换成别的年月日。`time.RFC3339` 就是这套布局的一个常数。示例的时刻在 UTC，所以结果以 `Z` 结尾。

`time.Time` 里可以带单调钟读数，用来做间隔测量。`Equal` 比较的是墙上时间，`==` 还会比较单调钟信息。两份从不同来源解析出来、墙上时间相同的 `Time`，`Equal` 为 true，`==` 可能为 false。比较时刻用 `Equal`。做超时和耗时用 `Since` 或 `Sub`。

## 文件与 bufio

读小文件用 `os.ReadFile`。它会把全文放进内存。按行读用 `bufio.Scanner`，默认单行上限 64 KiB，超长时 `Scan` 返回 false，用 `sc.Err()` 取原因。要接受更长的行，给 `Scanner` 设更大的缓冲区，同时自己定一个上限，避免一行把内存吃光。

打开文件先判断错误，成功后再 `defer f.Close()`。`Close` 的错误要用 [错误](A7-错误.md) 里的命名返回值和 `errors.Join` 留住，写文件时尤其重要：`Close` 才把缓冲区刷下去，忽略它会把「写了一半」当成成功。

`strings.Builder` 用来拼接大量字符串，避免在循环里用 `+` 反复复制。`fmt.Fprintf` 可以直接写到 `Builder`，也可以写到 `http.ResponseWriter`。

## 对比陷阱

| 做法 | 实际结果 |
| --- | --- |
| 用 `slices.Equal` 区分 nil 和空切片 | 两者被看成相等 |
| 把某次 `ns/op` 写进教程 | 数字只属于那台机器 |
| `t.Parallel` 的子测试共享一个 map | 数据竞争。循环变量在 1.22 之后是安全的，map 本身仍然不是 |
| `time.Time` 用 `==` 判断是不是同一时刻 | 单调钟信息不同时会失败。用 `Equal` |
| `omitempty` 放在数量字段上 | 0 会被省略，对方当成缺字段 |
| `filepath.Join(dir, userInput)` 直接打开 | 输入中的 `..` 可以离开 `dir` |

## 练习

1. 给 stdlib 示例加 `-repeat` 整数旗标，默认 1，把任务列表打印这么多遍。用 `flag.NewFlagSet` 测 0 和负数时程序返回错误。
2. 给 `NonEmptyLines` 加一行只有空格的输入，预测它会被丢掉。
3. 用 `time.Parse(time.RFC3339, "2026-01-02T15:04:05Z")` 得到时刻，再 `Format` 回去，确认字符串相同。

## 面试延伸

测试题说表驱动、`t.Run`、`Helper`、`Cleanup` 的后进先出，以及 Go 1.24 的 `t.Context` 会在 Cleanup 之前取消。基准题说 `for b.Loop()` 会把准备和清理排除在计时之外，并且禁止报一个与机器无关的纳秒数。时间题说参考时间是 `2006-01-02 15:04:05`，比较时刻用 `Equal`。路径题说 `filepath` 是本机路径，`path` 是斜杠路径，用户输入用 `os.Root` 限制。

## 问答题

### 问：`t.Fatal` 和 `t.Errorf` 怎么选？

前置条件不成立、后面再跑没有意义，用 `Fatal`，它结束当前测试函数。表里还有多条断言想一次看完，用 `Errorf`。辅助函数第一行写 `t.Helper()`，行号指向调用处。

### 问：`"a\r\n b"` 为什么变成 `a` 和 `b`？

`NonEmptyLines` 按行切开再 `TrimSpace`。`\r` 和空格被去掉。空输入返回 nil。`slices.Equal` 把 nil 和空切片看成相等，要区分时不要用它。

### 问：`Example` 失败时长什么样？

`// Output:` 下面的文本必须和程序输出逐字相同，包括空格和末尾换行。`go test` 会跑示例。示例是文档，不是可有可无的注释。

### 问：子测试开 `t.Parallel()` 要注意什么？

Go 1.22 起循环变量每次迭代一份，闭包看到的是当次用例。共享的 map 和切片仍然要自己同步。并行会打乱完成顺序，断言不要依赖别的子测试已经写完。

### 问：`t.Cleanup` 和 `defer` 在测试里怎么选？

`Cleanup` 在该测试和它的子测试都结束后执行，后注册的先执行。Go 1.24 起 `t.Context()` 在这些 Cleanup 之前取消。辅助函数替调用方注册清理时用 `Cleanup`，因为辅助函数的 `defer` 在辅助函数返回时就跑了。

### 问：`b.Loop` 和手写 `for i := 0; i < b.N; i++` 差在哪？

`Loop` 第一次调用时重置计时器，返回 false 时停表，准备和清理不算进去。循环体里的调用和赋值会被保留，避免编译器把循环删掉。条件必须写成 `for b.Loop()`。数字只属于这一次运行的机器。

### 问：`time.Format` 的数字为什么不能换？

布局参照 `2006-01-02 15:04:05`。写成 `2006-01-02` 是日期，写成 `2006-02-01` 就不是「年月日」了。`RFC3339` 是这套布局的一个常数。示例时刻在 UTC，所以以 `Z` 结尾。

### 问：`==` 比较两个 `time.Time` 为什么会失手？

`Time` 可以带单调钟。`Equal` 只比墙上时间，`==` 连单调钟一起比。从不同来源得到的同一时刻，用 `Equal`。测量间隔用 `Since` 或 `Sub`。

### 问：`omitempty` 会省略哪些值？

false、0、nil 指针、nil 接口，以及长度为零的数组、切片、map 和字符串。数量字段如果 0 是有意义的，不要加 `omitempty`。

### 问：`flag.Parse` 为什么不要放进库函数？

失败时它可能让进程退出。库和测试用 `flag.NewFlagSet` 配上 `ContinueOnError`，把错误返回给调用方。旗标要出现在普通参数前面。
