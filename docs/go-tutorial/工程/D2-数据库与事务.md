# D2 数据库与事务

`database/sql` 的 `*sql.DB` 是连接池，可以并发使用。`*sql.Tx` 绑在一条连接上，不要并发使用。`sql.Open` 不一定立刻连上数据库。示例驱动在 [examples/d2sql](../../../examples/d2sql/driver.go)，驱动名是 `sqltut`。

本章后半是 InnoDB 的概念，用来回答存储设计题。`sqltut` 没有实现这些机制。不要把教学驱动的测试结果说成 MySQL 的隔离级别。

## 这一章你要会什么

会用 `DB` 和 `Tx` 的差别写对事务，能说明 Go 1.27.1 里事务的 `Exec` 实际打在连接上，能把 MVCC、next-key、覆盖索引和深分页讲成概念而不是本仓库的测试。

## database/sql

`Open` 只检查驱动和参数，连接可以推迟到第一次查询。用完 `Close`。`DB` 自己管空闲连接和最大连接数。`SetMaxOpenConns`、`SetMaxIdleConns`、`SetConnMaxLifetime` 按数据库的连接上限来设。生命周期让连接定期换新，避免中间的防火墙先把空闲连接掐掉，而池还以为它活着。

`Query` 返回的 `Rows` 必须 `Close`。没关会占着连接，池会被耗尽。`Scan` 的参数是指针。没有行时 `QueryRow` 的 `Scan` 返回 `sql.ErrNoRows`。这是哨兵，用 `errors.Is` 判断，见 [错误](../地基/A7-错误.md)。

`Exec` 和 `Query` 都有 `Context` 后缀。context 取消时，驱动应当中断这次操作。已经执行完的语句不会因为取消而自动回滚，回滚要靠事务。

## 这条教学驱动实际做了什么

语句只有两种：`upsert` 写入字符串键和 `int64` 值，`get` 按键读出列 `v`。没有行时 `Scan` 得到 `sql.ErrNoRows`。

`BeginTx` 复制当时的 map 当快照。事务里的写入进自己的 dirty map。提交时只把 dirty 里的键写回共享 map，所以同一个键后提交的事务覆盖先提交的。不同键都会留下。回滚丢掉 dirty，不写回。事务里能读到自己的未提交写入。`driver.TxOptions` 被忽略，隔离级别参数不会改变这个行为。

这不是 MySQL 的可重复读，也不是快照隔离。它只用来看 `Begin`、`Commit`、`Rollback` 和 `ErrNoRows`。两个事务改不同的键都能留下，是因为提交按键合并。两个事务改同一个键，后提交的赢。InnoDB 在更高的隔离级别下会用锁让其中一个等待或失败，而不是默默覆盖。

Go 1.27.1 的 `database/sql` 里，`Tx.ExecContext` 和 `Tx.QueryContext` 最终调用的是连接上的 `ExecContext` / `QueryContext`，不会调用 `driver.Tx` 上的同名方法。所以连接自己记住当前事务，未提交的写入才看得见。`driver.Tx` 只实现 `Commit` 和 `Rollback`。

已取消的 context 上 `BeginTx` 返回 `context.Canceled`。

标准库里和这条驱动相关的加锁顺序是：先 `conn.mu`，再 `db.mu`。自己再包一层锁时不要反着来，避免和标准库的调用嵌套成死锁。教学驱动的 DSN 用测试名 `t.Name()`，让并行测试不共用一张 map。

```bash
go test ./examples/d2sql -count=1
```

## InnoDB 里面试要分清的概念

下面描述的是 MySQL InnoDB 的常见行为，不是 `sqltut`，本仓库也没有连着一个 MySQL 去跑它。版本不同，优化器的选择会变。回答时先说「这是 InnoDB 的机制」。

**Buffer Pool** 缓存数据页和索引页。读的时候先找池，没有再到磁盘。脏页之后刷回磁盘。池比数据小很多时，缓存命中率下降，查询时间会抖动。

**MVCC** 让读不必挡住写。一行的旧版本串在 undo 日志上。一致性读创建一个 Read View，按事务 ID 判断哪个版本对这次读可见。读已提交（RC）一般每次一致性读都建新的视图，所以同一事务里两次读可以看见别人刚提交的行。可重复读（RR）在事务的第一次一致性读建立视图，之后沿用，所以别人提交的修改不会出现在这次事务的普通 `SELECT` 里。这是快照读。`SELECT ... FOR UPDATE` 和 `UPDATE` 是当前读，读的是最新已提交版本，并加锁。

**锁。** 行锁锁住索引记录。间隙锁锁住索引记录之间的空隙，用来挡住别的事务把新行插进这个范围。Next-key lock 是记录锁加它前面的间隙。InnoDB 在 RR 下用它减少幻读：同一范围里不会突然多出一行让第二次当前读看见。条件如果是唯一索引的等值查找并且记录存在，可以退化成记录锁，不必再锁两边的间隙。死锁时 InnoDB 会回滚其中一个事务。应用看到死锁错误要重试整个事务，而不是只重试最后一条语句。

**覆盖索引** 是查询要的列都在一棵索引里，不必回表读整行。`EXPLAIN` 里能看见用了索引。多出来的列会让索引变宽，写入变贵。

**索引条件下推（ICP）** 让存储引擎在读索引时就用 `WHERE` 里能用上的条件过滤，少回表。它不改变结果，只减少无效的回表。

**深分页。** `LIMIT 100000, 20` 仍要数过前面的十万行。改写成先按索引取出这一页的主键，再按主键回表，这就是延迟关联。或者记住上一页最后一条的主键，用 `WHERE id > ? ORDER BY id LIMIT 20` 做按游标翻页。游标翻页不能直接跳到第 N 页。

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| `sqltut` 的提交结果就是 RR | 同键后提交覆盖先提交。没有锁，没有 undo |
| `sql.Open` 失败才说明数据库连不上 | `Open` 可以不连。要 `PingContext` 或第一次查询 |
| `Rows` 不关只是少一次函数调用 | 连接还在池外，池会被耗尽 |
| 事务里用了 context，失败会自动回滚 | 取消中断操作。回滚要 `Rollback` |
| RR 的普通 `SELECT` 和 `SELECT FOR UPDATE` 看见的一样 | 前者是快照读，后者是当前读 |
| 覆盖索引和 ICP 是同一种优化 | 覆盖索引是不必回表。ICP 是回表前先按条件下推过滤 |

## 面试延伸

Go 侧：`DB` 是池，`Tx` 是一条连接；`Open` 可以不连；`Rows` 要关；`ErrNoRows` 用 `errors.Is`；Go 1.27.1 的事务语句打在连接的 Exec/Query 上，驱动要在连接上记住事务。MySQL 侧先声明和 `sqltut` 无关，再讲 undo 加 Read View、RC 和 RR 建视图的时机、当前读的 next-key、覆盖索引、ICP、深分页改成延迟关联或游标。不要报一个本机没有跑过的 QPS。

## 问答题

### 问：`sql.Open` 失败才说明数据库挂了吗？

不是。`Open` 可以只检查驱动名和 DSN，连接推迟到第一次查询。要在启动时确认，用 `PingContext`。`DB` 是池，可以并发。`Tx` 绑一条连接，不要并发。

### 问：`Rows` 不关会怎样？

连接回不到池里。请求一多，`SetMaxOpenConns` 的上限被占满，后面的查询堵住。`Scan` 的参数是指针。没有行时 `QueryRow.Scan` 返回 `sql.ErrNoRows`，用 `errors.Is`。

### 问：`sqltut` 的提交到底合并了什么？

`BeginTx` 复制当时的 map。事务里的写进 dirty。提交只把 dirty 的键写回。同键后提交的赢，`TestSameKeyLastCommitWins` 锁住这一点。不同键都留下。回滚丢掉 dirty。事务里能读到自己的未提交写入。`TxOptions` 被忽略。

### 问：为什么驱动要在连接上记事务，而不是在 `driver.Tx` 上实现 `Exec`？

Go 1.27.1 的 `Tx.ExecContext` 和 `Tx.QueryContext` 调用的是连接上的方法，不会调用 `driver.Tx` 的同名方法。`driver.Tx` 只做 `Commit` 和 `Rollback`。连接不看当前事务的话，未提交的写会直接进共享 map，回滚也看不见。

### 问：已取消的 context 上 `BeginTx` 返回什么？

`context.Canceled`。`TestCanceledBegin` 锁住了。取消不会自动回滚一个已经开始的事务，回滚要自己调用。

### 问：这和 InnoDB 的 RR 差在哪？

`sqltut` 没有 undo，没有锁。同键后写覆盖。InnoDB 的 RR 用 Read View 做快照读，用 next-key 挡住当前读的幻读。回答时先说「下面是 InnoDB，不是这条教学驱动」。

### 问：RC 和 RR 的 Read View 何时建立？

读已提交一般每次一致性读都建新的视图，所以同一事务里两次普通 `SELECT` 可以看见别人刚提交的行。可重复读在第一次一致性读建立视图并沿用。`SELECT FOR UPDATE` 是当前读，读最新已提交版本并加锁。

### 问：唯一索引等值查找还要间隙锁吗？

记录存在时，InnoDB 往往可以退化成记录锁。范围条件和记录不存在时，间隙锁用来挡住别的事务把行插进来。死锁后重试整个事务，不要只重试最后一条语句。

### 问：深分页怎么改？

`LIMIT 100000, 20` 仍要数过前面的行。先按索引取出这一页的主键再回表，或写成 `WHERE id > ? ORDER BY id LIMIT 20`。游标翻页不能直接跳到第 N 页。覆盖索引是不必回表，ICP 是回表前先过滤，两件是不同的优化。
