# D2 数据库与事务

`database/sql` 的 `*sql.DB` 是连接池，可以并发使用。`*sql.Tx` 绑在一条连接上，不要并发使用。`sql.Open` 不一定立刻连上数据库。示例驱动在 [examples/d2sql](../../../examples/d2sql/driver.go)，驱动名是 `sqltut`。

## 这条教学驱动实际做了什么

语句只有两种：`upsert` 写入字符串键和 `int64` 值，`get` 按键读出列 `v`。没有行时 `Scan` 得到 `sql.ErrNoRows`。

`BeginTx` 复制当时的 map 当快照。事务里的写入进自己的 dirty map。提交时只把 dirty 里的键写回共享 map，所以**同一个键后提交的事务覆盖先提交的**。不同键都会留下。回滚丢掉 dirty，不写回。事务里能读到自己的未提交写入。`driver.TxOptions` 被忽略。

这不是 MySQL 的可重复读，也不是快照隔离。它只用来看 `Begin`、`Commit`、`Rollback` 和 `ErrNoRows`。

Go 1.27.1 的 `Tx.ExecContext` 和 `Tx.QueryContext` 最终调用的是**连接**上的 `ExecContext` / `QueryContext`，不会调用 `driver.Tx` 上的同名方法。所以连接自己记住当前事务，未提交的写入才看得见。`driver.Tx` 只负责 `Commit` 和 `Rollback`。

已取消的 context 上 `BeginTx` 返回 `context.Canceled`。

```bash
go test ./examples/d2sql -count=1
```
