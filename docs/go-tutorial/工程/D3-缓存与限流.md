# D3 缓存与限流

三个词指的是不同故障。实现都在 [examples/d3limit](../../../examples/d3limit/limit.go)，时钟由测试注入。

- **击穿**：热点键失效的瞬间，很多请求一起打到数据库。
- **穿透**：这个键本来就不存在，每次都穿过缓存。
- **雪崩**：大量键同时失效，或者缓存整体不可用。

`singleflight` 只合并「同一个 key 上还在执行的那一次调用」。函数返回后 map 里的记录被删掉，下一次会再执行。它不保存上一轮结果。穿透靠很短的负缓存。雪崩要靠过期时间加抖动，以及限流；示例没有做抖动。

## 缓存

`TTLCache` 在一把 `Mutex` 后面。`Get` 在 `now` 不再早于 `expires` 时视为未命中，到期时刻本身算过期。负缓存表示「确认没有」。不要把数据库故障缓存很久。`sync.Pool` 不是缓存，见 [同步与原子](../运行时/C5-同步与原子.md)。

## 令牌桶

`Allow` 按流逝时间补充 `elapsed * rate`，不超过 `burst`，再尝试取走 1 个。时间不前进就不补充，所以同一时刻最多通过 `burst` 次。测试里 `rate` 是 10、`burst` 是 2：起点过两次，第三次失败；100 毫秒后补充 1 个。

这是单机桶。全局限额要有共享计数。生产实现常用 `golang.org/x/time/rate`。

## 合并调用

`Group.Do` 里，后来的调用等待同一次 `WaitGroup`。`testing/synctest` 能等到这 8 个 goroutine 都堵在可等待的阻塞上，此时函数体只计数 1 次。放开之后再调一次，计数变成 2，说明结果没有被留成缓存。

`fn` 不能 panic。panic 发生在 `Done` 之前时，等待者会一直堵着。

```bash
go test ./examples/d3limit -count=1
```

## 练习

把 `burst` 改成 1，预测起点第二次 `Allow` 的结果，再改测试。
