# D4 熔断、重试与可观测性

示例在 [examples/d4svc](../../../examples/d4svc/breaker.go)。

## 重试预算

只重试幂等操作，或者带幂等键的写。重试次数要算进入口的 `context` 截止时间。时间到了就停，不要为了再试一次去用 `context.Background()`。取消怎么看，见 [上下文与日志](../能写服务/B2-上下文与日志.md)。

## 熔断

`Breaker` 有三个状态，测试用注入的时钟，阈值 2、冷却 1 秒：

- **关闭**：请求通过。连续失败达到阈值后打开。
- **打开**：冷却结束前拒绝。`now` 不再早于 `openUntil` 时，下一次 `Allow` 进入半开并放行一个探测。
- **半开**：同时只放一个探测。探测失败会重新打开，冷却从当前时间再算。探测成功调用 `Success` 后回到关闭，失败计数清零。

它不区分 4xx 和 5xx。讲状态机时把「还没做错误分类」一起说。

## 日志和指标

JSON `slog` 在 Info 级别下会记下 `msg` 和 `port`，不会出现 Debug 的 `hidden`。`Enabled(ctx, LevelDebug)` 为 false。参数在调用前就会求值，热路径先看 `Enabled`。

`runtime/metrics` 读取 `/memory/classes/total:bytes` 和 `/memory/classes/heap/released:bytes`。前者在正常进程里是非零的 `uint64`。名字写错时 `Kind` 是 `KindBad`，这时不能调用 `Uint64()`。两者相减就是 [垃圾回收](../运行时/C3-垃圾回收.md) 里内存软上限使用的那组量。不要用会 STW 的 `ReadMemStats` 做高频采集。

延迟看分位，不看会被快请求稀释的平均数。`pprof` 端点能看到栈和堆，不要挂到公网。`goroutineleak` 能发现什么，见 [接口、反射与剖析](../运行时/C6-接口反射与剖析.md)。

```bash
go test ./examples/d4svc -count=1
```
