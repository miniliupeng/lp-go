# D5 短链设计

设计题要说清数据怎么放、并发怎么保护、过期怎么处理，以及这一版故意没做的事。实现是 [examples/d5short](../../../examples/d5short/short.go)。

`Put` 给 URL 一个短码，`Resolve` 换回来。测试把 TTL 设成 1 分钟，时钟由调用方注入。

- 短码是递增计数的 62 进制。字母表是 `0-9`、`a-z`、`A-Z`。`seq` 从 0 开始，第一次 `Put` 先加 1，所以第一个码是 `"1"`，另一个 URL 是 `"2"`。
- 同一个 URL 在未过期时返回原来的短码。
- `ttl > 0` 时到期时间是 `now().Add(ttl)`。`Put` 和 `Resolve` 先丢掉已到期的记录。条件是 `now` 不再早于 `expires`，到期时刻本身算过期。到期后再 `Put` 同一个 URL，计数还在涨，得到新码。
- `ttl <= 0` 表示不过期。空字符串返回错误。
- 两张 map 和计数都在同一把 `Mutex` 后面。过期扫描也在这把锁里走完所有记录。

进程一退数据就没了。递增短码可以预测，公开服务应改成随机或哈希，冲突时重试。62 进制 6 位是 `62^6 = 56,800,235,584`。空间大仍然要处理冲突。

过期后本实现不会把刚用过的递增码立刻发给下一个 URL，因为计数不回头。随机码没有这个性质，不能把刚过期的码马上绑到另一个 URL。

跳转用 302 或 307。不要用 301：浏览器会长期记住永久跳转。这是 HTTP 的语义，不是 map 的语义。

规模上来之后，不要在在线请求的锁里扫全表。热门短码可以再加 [缓存与限流](D3-缓存与限流.md) 里的 TTL 和 singleflight。并发度如果用带缓冲的 channel 当信号量，容量规则见 [内存与逃逸](../运行时/C1-内存与逃逸.md)。

```bash
go test ./examples/d5short -count=1
```
