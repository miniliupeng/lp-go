# D5 短链设计

设计题要说清数据怎么放、并发怎么保护、过期怎么处理，以及这一版故意没做的事。实现是 [examples/d5short](../../../examples/d5short/short.go)。缓存、限流和消息语义分别在 [缓存与限流](D3-缓存与限流.md) 和 [熔断、重试与可观测性](D4-熔断重试与可观测性.md)。

## 这一章你要会什么

能按测试讲清短码怎么来、过期时刻算不算过期、为什么线上不能用递增码，并能把同一套设计题的问法用到「检索再生成」上，且不假装本仓库跑了一个向量库。

## 行为

`Put` 给 URL 一个短码，`Resolve` 换回来。测试把 TTL 设成 1 分钟，时钟由调用方注入。

- 短码是递增计数的 62 进制。字母表是 `0-9`、`a-z`、`A-Z`。`seq` 从 0 开始，第一次 `Put` 先加 1，所以第一个码是 `"1"`，另一个 URL 是 `"2"`。
- 同一个 URL 在未过期时返回原来的短码。
- `ttl > 0` 时到期时间是 `now().Add(ttl)`。`Put` 和 `Resolve` 先丢掉已到期的记录。条件是 `now` 不再早于 `expires`，到期时刻本身算过期。到期后再 `Put` 同一个 URL，计数还在涨，得到新码。
- `ttl <= 0` 表示不过期。空字符串返回错误。
- 两张 map 和计数都在同一把 `Mutex` 后面。过期扫描也在这把锁里走完所有记录。

进程一退数据就没了。这是单机教学实现。

## 短码

递增短码可以预测下一个是什么，也能从码的大小看出发了多少条。公开服务应改成随机或哈希，冲突时重试。62 进制 6 位是 `62^6 = 56,800,235,584`。空间大仍然要处理冲突，因为随机抽样会撞车，哈希也可能落到已有的码上。

过期后本实现不会把刚用过的递增码立刻发给下一个 URL，因为计数不回头。随机码没有这个性质。刚过期的码如果马上绑到另一个 URL，拿着旧链接的人会进到新地址。随机码要等一段冷却，或者永不复用。

跳转用 302 或 307。301 表示永久，浏览器和中间缓存会记住，你在服务端改了目标，客户端仍走旧地址。302 是临时，方法可能被改成 GET。307 保持方法和请求体。普通的短链跳转用 302 或 307，并在文档里写明。

## 规模

不要在在线请求的锁里扫全表。记录多了之后，过期放到后台按批删除，请求路径只查这一条。热门短码可以再加一层 TTL 缓存和 singleflight，避免热点把数据库打穿。

多副本时，递增计数要有一个分配器，每个副本领一段号，否则两个进程会发出同一个 `"1"`。随机码把冲突交给存储的唯一约束：插入失败就再抽一次。

存储可以是一张表：短码主键、URL、到期时间。解析用主键查。按 URL 反查原来的码需要另一棵索引。写入用事务保证两处一起成功。隔离级别和索引的概念在 [数据库与事务](D2-数据库与事务.md)，不要把 `sqltut` 的 map 说成这张表。

限流放在入口，挡住把短链当开放跳转来滥用的客户端。开放跳转是指允许用户把短码指到任意地址，从而借用你的域名做钓鱼。要限制目标主机，或者在跳转页上明示目标。

## 如果题目换成检索

有的设计题问「文档问答」：用户提问，系统从资料里找段落，再让模型生成回答。本仓库没有向量库，也没有模型。能讲的是边界：

1. 资料先切成段，段太长会超模型的上下文，段太短会丢上下文。每段记下文档号和偏移，回答要能指回原文。
2. 检索先按关键词，再按向量相似度，两路结果合并。只有向量时，专有名词可能找不到。只有关键词时，换一种说法就找不到。
3. 合并之后做一次重排，取前几段。把这几段和问题一起交给模型，并限制模型只根据这些段回答。
4. 超时沿用入口的 context。模型流式输出时按 [HTTP 超时与关闭](D1-HTTP超时与关闭.md) 的 SSE 来写：`Flush`，客户端断开就停，队列有界。
5. 同一段资料被很多请求检索时，用 D3 的缓存和 singleflight。不要在每次请求里重新嵌入全部文档。

没有评测集时，不要报一个召回率。召回率要有标注过的问题集才算得出来。

```bash
go test ./examples/d5short -count=1
```

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| 第一个短码是 `"0"` 或某个哈希 | 测试锁住第一个是 `"1"`，第二个是 `"2"` |
| 6 位 62 进制不用管冲突 | 空间是 56,800,235,584，随机仍然会撞 |
| 过期时刻还能解析 | `now` 不再早于 `expires` 就算过期 |
| 用 301 方便缓存 | 浏览器会长期记住永久跳转 |
| 在请求的锁里扫描全部过期键 | 数据一大，请求延迟跟着表的大小走 |
| 检索题报一个没标注过的召回率 | 没有评测集就算不出这个数 |

## 练习

1. 给 `Store` 加 `Len() int`，返回未过期的记录数。把时钟拨到到期时刻，断言 `Len` 变成 0。`Len` 要先做过期删除，并且拿同一把锁。
2. 算 `62^6`，再算如果每天发 1 亿条、用 6 位随机码，空间是否仍然远大于一天的量。冲突策略仍然要写出来。
3. 把跳转的状态码从 301 改成 302，用一句话说明浏览器缓存行为的差别。

## 面试延伸

先说数据：两张 map 加一把锁，教学实现，进程退出即丢。再说短码：递增 62 进制，第一个是 `"1"`，线上改随机或哈希并处理冲突，`62^6` 要报得出来。过期含边界，到期后再分配是新码。跳转用 302 或 307。规模题说不要在锁里全表扫描，热键加缓存和 singleflight，多副本不要共用内存计数。检索题按切段、两路召回、重排、引用原文、超时和 SSE 来讲，并声明本仓库没有向量库。

## 问答题

### 问：第一个短码为什么是 `"1"`？

字母表是 `0-9a-zA-Z`。`seq` 从 0 开始，`Put` 先加 1 再编码，所以第一个是 `"1"`，另一个 URL 是 `"2"`。不是哈希，也不是 `"0"`。测试锁住了这两个字符串。

### 问：`62^6` 是多少，还要处理冲突吗？

`56,800,235,584`。空间大，随机抽样和哈希仍然会撞上已有的码。冲突时再抽一次，存储用唯一约束拒绝重复。递增码能预测下一个，也能看出发了多少条，公开服务不用它。

### 问：到期时刻还能解析吗？

不能。条件是 `now` 不再早于 `expires`。到期后再 `Put` 同一个 URL，计数不回头，得到新码。`ttl <= 0` 表示不过期。空字符串返回错误。随机码刚过期不要马上绑到另一个 URL，否则旧链接会进到新地址。

### 问：为什么不用 301？

301 是永久跳转，浏览器会长期记住。服务端改了目标，客户端仍走旧地址。302 是临时，方法可能被改成 GET。307 保持方法和请求体。普通短链用 302 或 307。

### 问：锁里扫描全部记录有什么问题？

请求延迟跟着记录数走。过期放到后台按批删除，请求路径只查这一条。热门码加 TTL 缓存和 singleflight。多副本不要共用内存里的递增计数，否则两个进程都发出 `"1"`。随机码把冲突交给数据库的唯一约束。

### 问：开放跳转是什么？

允许用户把短码指到任意地址，别人可以借用你的域名做钓鱼。限制目标主机，或在跳转页上明示目标。入口再加限流。

### 问：表怎么建？

短码做主键，旁边是 URL 和到期时间。按 URL 反查原来的码需要另一棵索引。两处写入放在一个事务里。隔离级别和索引见 [数据库与事务](D2-数据库与事务.md)。`sqltut` 的 map 不是这张表。

### 问：检索题没有向量库时怎么答？

资料切成段并记下出处。关键词和向量两路召回，合并后重排，只把前几段交给模型。超时用入口 context，输出按 SSE 写，客户端断开就停。同一批资料不要每次重新嵌入。没有评测集就不要报召回率。本仓库没有向量库，也没有模型。
