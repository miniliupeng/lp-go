# B1 goroutine、channel 与 WaitGroup

`go f()` 启动一个 goroutine。它和当前函数并发执行。函数返回不会等待它。示例在 [examples/b1conc](../../../examples/b1conc/conc.go)。

## channel

`SumSquares(4)` 启动 4 个 goroutine，每个把 `i*i` 送进同一个 channel。主 goroutine 接收恰好 4 次，所以不需要 `close`。Go 1.22 起每次迭代有自己的 `i`，闭包里的 `i` 是当次的值。1 到 4 的平方和是 30。

无缓冲 channel 的发送和接收要配对。谁先到，谁等待。把 channel 变量设成 nil 之后，对它发送或接收会永远阻塞；放在 `select` 的 case 里时，这个 case 永远不会被选中。关闭规则和 `select` 的随机选择放在 [C4](../运行时/C4-通道与选择.md)，这里先记住：只由发送方，或唯一负责关闭的那一方，关闭 channel。

`First` 在数据和停止两个 channel 里取一个。测试每次只让其中一个就绪。两个都就绪时，规范要求用均匀的伪随机选一个，测试不能断言一定走哪边。

## WaitGroup

`SumSquaresLocked` 用 `sync.WaitGroup`。Go 1.27 的 `WaitGroup.Go(f)` 会 `Add(1)`，`f` 返回后 `Done`。文档要求 `f` 不要 panic。`Wait` 要在至少一次 `Add` 之后调用；计数已经是 0 时，后补的 `Add` 配不上这次 `Wait`。

累加共享变量 `sum` 时用 `Mutex`。没有这把锁，两个 goroutine 同时 `sum +=` 就是数据竞争。`go test -race` 能抓住测试正好撞上的这种写。

`go` 语句本身会在新 goroutine 开始执行之前建立 happens-before。goroutine 退出不会自动把写入同步给别人，所以结束前要用 channel、`Wait` 或锁把结果交出去。详见 [C1](../运行时/C1-内存与逃逸.md)。

```bash
go test ./examples/b1conc -count=1
```

## 练习

把 `SumSquares` 的参数改成 0，确认它返回 0，并且不会卡在接收上。
