# B2 context 与 slog

`context.Context` 携带截止时间、取消信号和少量请求范围的值。取消它不会把 goroutine 杀掉。函数要自己看 `ctx.Err()`，或者把 `ctx` 传给 `net/http`、`database/sql` 这类会监听它的 API。示例在 [examples/b2ctx](../../../examples/b2ctx/run.go)。

## Cause

`RunSteps` 每一步先看 `ctx.Err()`。已经结束时返回 `context.Cause(ctx)`：

- context 还没结束时，`Cause` 返回 nil。
- `WithCancelCause` 的 `cancel(err)` 之后，`Err()` 仍是 `context.Canceled`，`Cause` 返回你传入的 `err`。`cancel(nil)` 时原因就是 `Canceled`。源码里取消函数调用的是 `cancel(true, Canceled, cause)`，cause 为空就用 `Canceled`。
- `WithTimeout` 到期后，`Err` 和 `Cause` 都是 `context.DeadlineExceeded`。

不要写成 `select` 同时等 `ctx.Done()` 和 `default`。context 已经取消时两边都就绪，`select` 会随机选一个，取消可能被丢掉。

超时测试放在 `testing/synctest` 里。气泡内的 `time.Sleep` 和 `WithTimeout` 使用假时钟，测试不用真的等一秒。`synctest.Wait` 会等到气泡里的 goroutine 都停在可等待的阻塞上。

## 请求号和日志

`WithRequestID` 用私有的键类型 `requestIDKey` 把字符串放进 context。不要把可选的业务参数、数据库连接都塞进 context。

`log/slog` 的 JSON Handler 一行一个对象。`logger.With("request_id", id)` 之后，`Info("hello")` 的输出里有 `"request_id":"req-7"`。级别过滤发生在 Handler；调用 `Debug` 时参数仍会先求值。极热路径先看 `Enabled`。

```bash
go test ./examples/b2ctx -count=1
```

## 练习

在 `RunSteps` 的测试里再取消一次已经取消的 context，确认 `Cause` 仍是第一次的原因。
