# B5 泛型与迭代器

示例在 [examples/b5gen](../../../examples/b5gen/set.go)。Go 1.18 引入类型参数。本仓库用 Go 1.27.1 编译，泛型方法和提升字段字面量键都在这个版本上跑过。

## 这一章你要会什么

会给容器写类型参数，知道 `comparable` 和 `~` 各限制什么，能说明泛型方法为什么不能用来实现接口，会写一个 `yield` 返回 false 就停下的迭代器。

## 什么时候用类型参数

类型参数适合容器和算法：集合、映射、树、对一片元素做变换。调用方在编译期就确定元素类型，函数体内不必做类型断言。

能用小接口写清楚时，不必上类型参数。`io.Reader` 表达的是行为。换成 `func Read[T any](...)` 并不能把「能读」说得更清楚。参数是 `any`、函数里再断言出三种具体类型，那是把编译期检查推迟到了运行期，见 [接口](../地基/A6-接口.md)。

## 约束

`Set[T comparable]` 的元素必须能用 `==` 比较，所以约束是 `comparable`。`comparable` 包括布尔、数值、字符串、指针、channel、接口，以及字段都可比较的数组和结构体。切片、map 和函数不能当 `comparable` 的类型实参。

`MapSlice[S ~[]E, E any, R any]` 里的 `~[]E` 表示底层类型是 `[]E` 的类型，包括 `[]int` 和你自己定义的 `type Ints []int`。没有 `~` 时，`[]E` 只匹配切片本身，不匹配命名后的 `Ints`。函数体里按约束所允许的操作来用。`any` 表示不要求任何操作。

类型推断能从参数推出 `E` 时，调用方不必写 `MapSlice[Ints, int, string](...)`。推断失败时编译器会指出缺了哪一个类型。不要为了少写类型实参而把函数签名改得看不懂。

## 泛型方法

Go 1.27 可以写 `func (Box) Identity[T any](v T) T`。接口方法不能带类型参数。泛型方法也不能用来实现接口方法。需要「对很多类型做同一件事」并且要放进接口时，继续用接口，或者用类型参数写函数而不是方法。

这条限制来自接口表要在编译期排好方法。每个接口方法对应一个具体的函数签名。类型参数要等到调用才确定，排不进这张表。

## 提升字段

`outer{X: 7}` 在 Go 1.27.1 里合法，`X` 是嵌入的 `inner` 提升上来的字段名。选择器 `Inner.X` 不能当字面量键。这和泛型无关，放在同一组测试里，是为了把「1.27 才编译得过」的写法收在一处。规则见 [函数、结构体与方法](../地基/A5-函数结构体与方法.md)。

## 迭代器

Go 1.23 起 `for range` 可以遍历 `iter.Seq[V]`，它的类型是 `func(yield func(V) bool)`。`iter.Seq2[K, V]` 是 `func(yield func(K, V) bool)`。

`yield` 返回 false 时必须停，并且不能再调用 `yield`，否则 panic。`break`、`return` 或循环里的 `continue` 到外层，都会让 `yield` 返回 false。`CountDown(5)` 在 3 处 break，得到 `5, 4, 3`。

这种迭代器是推送式的：函数自己决定下一个值什么时候算。调用方不先要一份完整切片。管道如果只取前三个元素，后面的元素可以不算。这和先 `append` 到切片再返回不同。切片的好处是可以随机访问、可以看 `len`。迭代器的好处是个数很大或无穷时不必先物化。两种都要会，按调用方需不需要随机访问来选。

`maps.Keys`、`slices.Values`、`slices.All` 返回的就是这种迭代器。`maps.Keys` 的顺序和直接 `range` map 一样，没有排序。

迭代器函数里如果启动 goroutine 再往 `yield` 里送，调用方 `break` 之后你仍可能再调用 `yield`，那会 panic。简单的迭代器在调用 `yield` 的同一个 goroutine 里同步产生值。

## 对比陷阱

| 写法 | 实际结果 |
| --- | --- |
| 用切片当 `Set` 的类型实参 | `comparable` 不允许 |
| `type Ints []int` 去匹配没有 `~` 的 `[]int` 约束 | 编译失败。要写 `~[]int` |
| 想用泛型方法实现接口 | 不允许。接口方法不能有类型参数 |
| `yield` 返回 false 之后继续调用 | panic |
| 在另一个 goroutine 里调用 `yield` | `break` 之后容易再进入 `yield` |
| 以为 `maps.Keys` 的顺序稳定 | 和 range map 一样不稳定 |

## 练习

1. 给 `Set` 加 `Len() int`。用 `int` 写测试。再在一个临时文件里用 `[]int` 当类型实参，确认编译失败，然后删掉这个文件。
2. 写一个 `iter.Seq[int]`，依次产生 1、2、3。`range` 时在 2 处 `break`，确认函数没有继续产生 3。可以让它在被要求停止后把一个计数器留下，测试只断言计数器。
3. 用 `slices.Values` 遍历一段切片，在循环里只累加，不把元素收集成新切片。

## 面试延伸

类型参数用于容器和算法，行为用接口。`comparable` 排除切片、map 和函数。`~` 把底层类型算进来。泛型方法在 Go 1.27 可以写在具体类型上，但不能实现接口方法。迭代器从 Go 1.23 开始，`yield` 返回 false 必须停止，`break` 就是让它返回 false。不要给迭代器报一个与机器无关的「零分配纳秒数」。

## 问答题

### 问：`Set[T comparable]` 能装切片吗？

不能。`comparable` 要求能用 `==`。切片、map 和函数都不行。布尔、数值、字符串、指针、channel、字段都可比较的结构体可以。

### 问：`type Ints []int` 为什么有时匹配不了 `[]int` 的约束？

没有 `~` 时，`[]E` 只匹配切片类型字面本身。`~[]E` 把底层类型是 `[]E` 的命名类型也算进来。`MapSlice` 用的是 `~`。

### 问：什么时候不要用类型参数？

行为已经能用小接口说清，例如 `io.Reader`。参数是 `any` 再断言出三种类型，只是把检查推迟到运行期。类型参数适合容器和算法。

### 问：泛型方法为什么不能实现接口？

接口的方法表要在编译期排好，每个方法一个具体签名。类型参数要到调用才确定。Go 1.27 可以在具体类型上写 `Identity[T any]`，但不能拿它去实现接口方法。

### 问：`outer{X: 7}` 和泛型有关系吗？

没有。它是 Go 1.27.1 的提升字段字面量键，和泛型方法放在同一组测试里，是因为两者都要 1.27 的工具链才编译得过。选择器不能当键。

### 问：`yield` 返回 false 之后继续调用会怎样？

panic。`break` 会让 `yield` 返回 false。`CountDown(5)` 在 3 处 break，得到 `5, 4, 3`。不要在另一个 goroutine 里调用 `yield`，调用方 break 之后你可能再进去。

### 问：迭代器和先收集成切片怎么选？

调用方要随机访问或 `len`，用切片。只往前走、后面的元素可能不需要，用 `iter.Seq`，避免先物化整份。`maps.Keys` 的顺序仍然不稳定。

### 问：`iter.Seq2` 是什么？

`func(yield func(K, V) bool)`。键和值一起交出来。停止规则和 `Seq` 一样：`yield` 返回 false 就停。
