# B6 目录、vet 与竞态

本教程把示例放在 `examples/`，章节放在 `docs/go-tutorial/`，是为了和 A1–E3 对上。做一个服务时，常见布局是：

```text
module/
  go.mod
  cmd/server/main.go
  internal/httpapi/
  internal/store/
```

`main` 只解析参数、组装依赖、启动服务。可测试的逻辑放在库包里，接受 `io.Reader`、`http.Handler`，而不是去读全局变量。`internal` 的导入限制见 [A8](../地基/A8-包与模块.md)。不要建一个什么都往里放的 `util` 包。

提交前在仓库根目录：

```bash
go fmt ./examples/...
go vet ./examples/...
go test ./examples/...
```

`go fmt` 走 `go.mod` 指定的工具链。`go vet` 默认跑全部分析器，和这套教程直接相关的有：

- `printf`：格式串和参数不一致。Go 1.27 起，`%w` 的操作数如果是 `*E` 而 `E` 实现了 `error`，会报告这破坏 `errors.Is`。
- `stringintconv`：`string(整数)` 得到的是码点。
- `copylocks`：按值复制了 `sync.Mutex`。
- `lostcancel`：`context.WithCancel` 的 `cancel` 没有被调用。
- `stdversion`：用了比当前文件版本更新的标准库符号。文件版本来自 `go.mod` 的 `go` 行。这个分析器在工具链低于 1.22 时会自己关掉。

`go vet` 的文档写明它是启发式的。过了 vet 不等于程序正确。

```bash
go test -race ./examples/...
```

`-race` 能抓住测试跑到的、没有同步的并发写。没跑到的路径它看不见。

标准库够用就不要加依赖。令牌桶的生产实现常用 `golang.org/x/time/rate`，[D3](../工程/D3-缓存与限流.md) 里的桶是为了把规则测清楚。`go.sum` 要提交。升级依赖的方式是改版本再 `go mod tidy`。

## 练习

执行 `go vet ./examples/...`。没有输出且退出码为 0，表示这组分析器没有报告。
