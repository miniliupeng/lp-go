# B6 目录、vet 与版本界线

本教程把示例放在 `examples/`，章节放在 `docs/go-tutorial/`，是为了和 A1–E3 对上。做一个服务时按这一节的目录来放。版本只写本教程已经在 Go 1.27.1 上用过、或能在这份工具链源码里对上的变化。

## 这一章你要会什么

会把可执行文件和库分开，知道提交前跑哪三条命令，能解释 `go vet` 里和本教程相关的分析器，能按版本说出循环变量、路由、迭代器和 JSON 这些行为从哪一档开始算。

## 服务目录

```text
module/
  go.mod
  cmd/server/main.go
  internal/httpapi/
  internal/store/
```

`main` 只解析参数、组装依赖、启动服务。可测试的逻辑放在库包里，接受 `io.Reader`、`http.Handler` 或一个小接口，而不是去读全局变量。`internal` 的导入限制见 [包与模块](../地基/A8-包与模块.md)。

不要建一个什么都往里放的 `util`。名字说明不了依赖方向。按领域放：`internal/shorturl`、`internal/ratelimit`。标准库够用就不要先加一个框架。

配置从 `flag` 或环境变量读进一个结构体，再传给构造函数。不要在包级 `init` 里读环境并打开连接。

## 提交前

在仓库根目录：

```bash
go fmt ./examples/...
go vet ./examples/...
go test ./examples/...
```

`go fmt` 走 `go.mod` 指定的工具链。系统里的旧 `gofmt` 不认识泛型方法。

`go vet` 默认跑一组分析器。和这套教程直接相关的有：

| 分析器 | 它在找什么 |
| --- | --- |
| `printf` | 格式串和参数不一致。Go 1.27 起，`%w` 的操作数如果是 `*E` 而 `E` 实现了 `error`，会报告这破坏 `errors.Is` |
| `stringintconv` | `string(整数)` 得到的是码点，不是十进制文本 |
| `copylocks` | 按值复制了 `sync.Mutex` 或含有锁的结构体 |
| `lostcancel` | `context.WithCancel` 的 `cancel` 没有被调用 |
| `stdversion` | 用了比当前文件版本更新的标准库符号。文件版本来自 `go.mod` 的 `go` 行，或文件顶部的 `//go:build go1.X`。工具链低于 1.22 时这个分析器会自己关掉 |
| `httpresponse` | 写了 HTTP 响应之后没有 `return`，后面的代码又写了一次 |
| `loopclosure` | 在 Go 1.21 及更早的语言版本下，闭包捕获了循环变量。本仓库的 `go` 行是 1.27.1，循环变量每次迭代一份，这条规则按文件版本判断 |

`go vet` 的文档写明它是启发式的。过了 vet 不等于程序正确。`go test -race ./examples/...` 能抓住跑到的数据竞争，没跑到的路径它看不见。

## 版本界线

下面的界线是本教程正文的约定。某一行写「Go 1.22 起就成立」，表示从 1.22 往后可以当默认行为用，不表示每一项都是 1.22 那一天加进来的。

| 档 | 在本教程里怎么用 |
| --- | --- |
| Go 1.22 起就成立 | 每次循环迭代有自己的循环变量；`for i := range n`；`net/http.ServeMux` 可以写方法和 `{id}`；`log/slog`；`slices` / `maps`；`errors.Join`；`context.WithCancelCause` |
| Go 1.23 起就成立 | `for range` 遍历 `iter.Seq`；计时器通道按同步通道来用。Go 1.27 删除了 `asynctimerchan` 这个 GODEBUG，本工具链上 `cap(time.NewTimer(d).C)` 是 0 |
| Go 1.24 起就成立 | `os.OpenRoot`；`t.Context()` 在 Cleanup 之前取消 |
| 在 Go 1.27.1 上写过并跑过 | 泛型方法；结构体字面量用提升字段的名字当键；`encoding/json` 的 v1 重复键后写覆盖；`encoding/json/v2` 拒绝重复键；`testing/synctest`；`WaitGroup.Go`；`runtime/pprof` 的 `goroutineleak` |
| 默认关闭 | `GOEXPERIMENT=greenteagc` 才打开 Green Tea GC。`internal/goexperiment/exp_greenteagc_off.go` 里 `GreenTeaGC` 为 false。`GOEXPERIMENT=nojsonv2` 用来退回旧的 JSON 实现，新代码不要依赖它 |

`testing.B.Loop` 在这份工具链里存在：第一次调用重置计时器，`for b.Loop()` 的循环体不会被完全优化掉。基准数字仍只属于跑它的那台机器。

标准库够用就不要加依赖。令牌桶的生产实现常用 `golang.org/x/time/rate`，[缓存与限流](../工程/D3-缓存与限流.md) 里的桶是为了把规则测清楚。一旦有了第三方模块，`go.sum` 要提交。升级的方式是 `go get` 指定版本再 `go mod tidy`。算法见 [包与模块](../地基/A8-包与模块.md)。

## 对比陷阱

| 做法 | 实际结果 |
| --- | --- |
| 用系统旧 `gofmt` 格式化含泛型方法的文件 | 报语法错误。用 `go fmt` |
| 过了 `go vet` 就认为没有数据竞争 | vet 不替代 `-race`，`-race` 也不替代没写的测试 |
| 把 Green Tea 说成 Go 1.27 的默认 GC | 默认构建里 `GreenTeaGC` 为 false |
| 在 `init` 里连接数据库 | 测试导入包就会连接 |
| 把 `util` 包当成依赖方向 | 所有包都去依赖它，循环导入和边界会糊掉 |

## 练习

1. 执行 `go vet ./examples/...`。没有输出且退出码为 0，表示这组分析器没有报告。
2. 执行 `go env GOVERSION`，确认在仓库根目录是 `go1.27.1`。
3. 把上面的版本表里「1.27 上跑过」的四项，分别指出本教程哪一章的测试在锁它们。

## 面试延伸

目录题：`cmd` 里只有组装，逻辑在 `internal`，`internal` 由编译器限制导入。检查题：`go fmt`、`go vet`、`go test`，竞态再加 `-race`。版本题按表回答，并主动说 Green Tea 和 `nojsonv2` 不是默认行为。`stdversion` 从 Go 1.22 起按 `go` 行判断文件能用哪些标准库符号。

## 问答题

### 问：`main` 里应该写业务规则吗？

不写。`main` 解析参数、组装依赖、启动服务。规则放在库包里，接受接口或 `io.Reader`，测试不必启动进程。`init` 里不要连接数据库。

### 问：为什么不要建 `util` 包？

名字不说明依赖方向，所有包都会去依赖它，最后谁也拆不走。按领域放，例如 `internal/shorturl`。标准库够用就不要先加框架。

### 问：`go vet` 过了等于没有数据竞争吗？

不等于。vet 是启发式。`-race` 只看见跑到的路径。两者都要跑，也都代替不了没写的测试。

### 问：`printf` 在 Go 1.27 多报了什么？

`%w` 的参数是 `*E` 且 `E` 实现了 `error` 时，报告这会破坏 `errors.Is`。`stringintconv` 提醒 `string(整数)` 是码点。`copylocks` 抓按值复制的锁。`lostcancel` 抓没有调用的 `cancel`。

### 问：`stdversion` 看的版本从哪来？

`go.mod` 的 `go` 行，或文件顶部的 `//go:build go1.X`。工具链低于 1.22 时这个分析器自己关掉。本仓库是 1.27.1，用了比这行更新的标准库符号才会报。

### 问：Green Tea 是默认 GC 吗？

不是。`GOEXPERIMENT=greenteagc` 才打开。默认文件 `exp_greenteagc_off.go` 里 `GreenTeaGC` 为 false。正文讲的是默认的标记-清除。

### 问：`nojsonv2` 应该写进生产构建吗？

它是过渡开关，用来退回旧的 JSON 实现。新代码按 `encoding/json` 或 `encoding/json/v2` 里你选定的行为来写。重复键的差别以测试为准，见 [JSON 与文件](B4-JSON与文件.md)。

### 问：第三方依赖什么时候才加？

标准库覆盖不了、而且你愿意提交 `go.sum` 的时候。令牌桶的生产实现常用 `golang.org/x/time/rate`，教程里的桶是为了把规则测清楚。升级用 `go get` 指定版本再 `go mod tidy`。
