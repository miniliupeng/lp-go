# C1 内存、逃逸与内存模型

这一章对照 Go 1.27.1 的 `runtime/malloc.go`、`runtime/slice.go` 和语言内存模型。垃圾回收的标记过程在 [垃圾回收](C3-垃圾回收.md)。不要把某台机器上的分配次数或纳秒数写成结论。

## 这一章你要会什么

能看懂逃逸分析的 `-m` 输出在说什么，能按 `malloc.go` 的层次说明小对象从哪分配，能说出切片扩容公式和它不是语言常数，能用 happens-before 判断另一个 goroutine 能不能看见这次写入。

## 逃逸

函数返回局部变量的地址时，这个变量不能只活在栈上。`Leak` 返回 `&n`，Go 1.27.1 的编译器在 `-m` 输出里写 `moved to heap`。更早的编译器常写 `escapes to heap`。测试两种措辞都接受，并且要求输出里有 `Leak`。`Stay` 只返回一个整数，参数不必逃逸。

```bash
go test ./examples/c1escape -count=1
```

逃逸是编译器的决定。取地址之后如果指针没有离开函数，编译器仍然可以把它留在栈上。接口、切片、`append` 的底层数组、闭包捕获的变量，都可能因为「生命周期超过这次调用」而到堆上。栈分配由函数返回时回收。堆上的内存等垃圾回收。

看一份具体的函数时，用 `go build -gcflags=-m` 看这一版编译器的结论，不要背「取地址一定上堆」。

## 分配器

`runtime/malloc.go` 开头写明：分配器按页管理，小对象（含 32 KiB，`internal/runtime/gc` 里 `MaxSmallSize = 32768`）会进大小类。大小类一共 `NumSizeClasses = 68`，其中 0 号不用，所以大约七十档里实际用到的是一张固定的尺寸表，例如 8、16、24、32。页的粒度是 8192 字节。这些数字是这份源码里的常数，不是语言规范。

分配器的结构，按文件头的原话：

| 名字 | 作用 |
| --- | --- |
| `mheap` | 按页管理堆 |
| `mspan` | 由 `mheap` 管理的一段正在使用的页 |
| `mcentral` | 收集某一个大小类的 span |
| `mcache` | 每个 P 一份的 span 缓存，分配时不必先拿锁 |
| `fixalloc` | 给分配器自己的固定大小、堆外对象用的空闲链表 |

小对象的路径也是文件头写的：

1. 把尺寸向上取到大小类，在当前 P 的 `mcache` 里找对应 span，扫空闲位图。有空位就分配，不必加锁。
2. 这个 span 没有空位时，向 `mcentral` 要一个还有空位的 span。一次拿一整段，把加锁的成本摊掉。
3. `mcentral` 也没有时，向 `mheap` 要一段页来做新的 span。
4. `mheap` 没有足够的页时，向操作系统再要至少 1MB 的页。一次多要一些，把系统调用的成本摊掉。

无指针的极小对象可以走 tiny allocator，几个对象拼在一个块里。它是优化。面试把上面四级说清即可。

大于小对象上限的分配直接按页从堆上取，不再进大小类。

`make` 切片、`new`、map 的桶、channel 的缓冲，最终都走到这套分配器。切片头、map 头本身很小，底层数组和桶可能大得多。

没有指针、并且比 tiny 块更小的对象，可以拼进当前 P 的 tiny 块里。Go 1.27.1 的 `internal/runtime/gc` 把 `TinySize` 定为 16，对应的大小类是 2。`malloc.go` 写明这种对象不能被单独 `free`，主要用来装很小的字符串和逃逸出去的小变量。几个逻辑对象共用一块内存，所以「一次 `new` 就对应一次你能在剖面里单独看见的分配」并不总是成立。

`weak.Pointer` 不让对象保持可达。对象除了弱指针之外没有别的引用时，`Value` 可以返回 nil。文档同时写明：不保证最终一定会变成 nil。极小且没有指针的对象可能被拼在同一个槽里，其中一个还活着时，旁边那个的弱指针可能一直不变成 nil。弱指针相等比较的是对象和对象内部的偏移，不是复活之后的新地址。缓存如果用弱指针，未命中要能重新加载，不能把 `Value() == nil` 当成「已经终结」的唯一信号。`unique.Handle` 则是另一件事：相等的值共享同一个身份，`Make` 对并发安全，比较句柄比比较大字符串便宜。句柄会保住那个值，它不是弱引用。

## 切片扩容

`runtime/slice.go` 的 `nextslicecap`：需要的新长度大于旧容量的两倍时，直接用新长度；旧容量小于 256 时翻倍；否则 `newcap += (newcap + 3*256) >> 2`，大约按 1.25 倍增长。之后还会按大小类向上取整，所以你观察到的 `cap` 可以比这个函数的返回值更大。它不是语言规范规定的常数，换一个 Go 版本之前要重新看源码。

容量还够时，`append` 写进原来的底层数组。两个切片共享这段数组时，写入会互相看见。见 [类型](../地基/A3-类型.md) 的测试。容量不够时换新数组，旧切片头不变。

三下标切片 `s[i:j:k]` 把新切片的容量限制成 `k-i`。把一段切片交给别的函数之前用它，对方的 `append` 就不会写进你还要使用的后半段。

## 内存模型

Go 的内存模型是 DRF-SC：没有数据竞争的程序，行为按顺序一致性理解。有数据竞争的程序没有这个保证。下面几条用来判断「另一个 goroutine 能不能看见这次写入」：

- `go` 语句的执行 happens before 新 goroutine 开始。
- goroutine 退出本身不把写入同步给别人。
- channel 上的发送 happens before 对应的那次接收完成。
- 关闭 channel happens before 因为关闭而收到零值的那次接收完成。
- 无缓冲 channel 上，接收 happens before 对应的发送完成。
- 容量为 C 的 channel 上，第 k 次接收 happens before 第 k+C 次发送完成。因此带缓冲的 channel 可以当计数信号量：缓冲里的空位就是同时持有的名额。满了之后发送方阻塞，接收一次就腾出一个名额。
- 第 n 次 `Unlock` happens before 第 m 次 `Lock` 返回，其中 n < m。失败的 `TryLock` 不建立同步。
- 原子操作：如果 B 观察到了 A 的结果，则 A happens before B。`sync/atomic` 的操作是顺序一致的。

只把变量写成 `atomic.Int64` 还不够组成临界区。两个原子变量各自原子，中间的判断和写入仍然会交错。复合动作用 `Mutex`，让锁把几步包进同一个 happens-before。

32 位平台上，自己把 `uint64` 拆开放进结构体再做原子操作，对齐可能不对。用 `atomic.Int64`，由类型保证对齐。

包初始化也有顺序：如果 `p` 导入 `q`，`q` 的 `init` 完成 happens before `p` 的初始化。见 [包与模块](../地基/A8-包与模块.md)。

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| 取地址就一定分配到堆上 | 指针不离开函数时，编译器可以留在栈上。以 `-m` 为准 |
| 背一个永远成立的扩容倍数 | `nextslicecap` 还有大小类取整，而且不是语言规范 |
| 有缓冲 channel 只是「快一点的队列」 | 第 k 次接收同步第 k+C 次发送，可以当信号量 |
| 失败的 `TryLock` 也建立了 happens-before | 不建立 |
| 两个原子写保护了一段复合逻辑 | 各自原子，复合动作仍要锁 |
| 把某次 benchmark 的 `allocs/op` 当成分配器行为 | 那是那次运行的计数。分配器行为看 `malloc.go` |

## 练习

1. 给 `Leak` 加一个只在函数内部取地址、又不返回的变量，用 `-gcflags=-m` 看编译器怎么说。把结论写在测试注释里，不要把某一版的英文提示当成永远不变的字符串。
2. 用容量为 2 的 channel 做信号量：同时最多两个 goroutine 打印「进入」。用 `WaitGroup` 等它们结束。
3. 画出 `append` 的两条路：容量够时共享底层数组，容量不够时旧切片头不变。用 [类型](../地基/A3-类型.md) 里已有的测试对一下。

## 面试延伸

逃逸题先说「生命周期超过栈帧才会到堆上」，再提 `-m` 的措辞会变。分配题按 mcache、mcentral、mheap、操作系统四级说，页是 8192，小对象上限是 32 KiB，大小类数量以源码的 68 为准并说明 0 号不用。扩容题背公式的三个分支，并说还会按大小类取整。内存模型题至少说出：`go` 同步启动，退出不同步，无缓冲 channel 的接收先于发送完成，容量 C 的第 k 次接收先于第 k+C 次发送完成，失败的 `TryLock` 不同步。

## 问答题

### 问：`Leak` 的 `-m` 输出一定写 escapes to heap 吗？

不一定。Go 1.27.1 常写 `moved to heap`。测试两种措辞都接受，并且要求输出里有 `Leak`。`Stay` 只返回整数，参数不必逃逸。措辞会随编译器变，结论以这次 `-m` 为准。

### 问：取了地址就一定在堆上吗？

指针不离开函数时，编译器可以留在栈上。接口、闭包、返回的指针、`append` 换出来的底层数组，才是常见的逃逸原因。栈上的内存在函数返回时回收。

### 问：小对象的四级路径是什么？

`malloc.go` 写的是：先在当前 P 的 `mcache` 里按大小类找 span 的空位，不必加锁；没有空位就向 `mcentral` 要一整段 span；再没有就向 `mheap` 要页；堆上也没有就向操作系统要至少 1MB 的页。页是 8192 字节。小对象含 32 KiB。`NumSizeClasses` 是 68，0 号尺寸是 0。

### 问：大于 32 KiB 的对象走大小类吗？

不走。直接按页从堆上取。切片头本身很小，底层数组可能大得多，两者不要混成一次分配。

### 问：`nextslicecap` 的三个分支？

新长度大于旧容量的两倍，用新长度。旧容量小于 256，翻倍。否则 `newcap += (newcap + 3*256) >> 2`。然后按大小类向上取整，所以观察到的 `cap` 可以更大。这不是语言规范。

### 问：容量为 2 的 channel 怎么当信号量？

第 k 次接收 happens before 第 k+2 次发送完成。缓冲里的空位就是名额。先发送两次占满，第三次发送阻塞，直到有人接收。无缓冲时，接收先于对应的发送完成。

### 问：失败的 `TryLock` 算同步吗？

不算。只有成功的锁配对才建立 happens-before：第 n 次 `Unlock` 先于更后的 `Lock` 返回。两个原子操作各自原子，中间的复合判断仍然要锁。

### 问：32 位平台上原子变量怎么写？

用 `atomic.Int64`，由类型保证对齐。不要自己拿可能没对齐的 `uint64` 地址去做 64 位原子。

### 问：有数据竞争时还能用顺序一致性推理吗？

不能。DRF-SC 的前提是没有数据竞争。竞争程序的行为没有这个保证，`-race` 用来抓测试跑到的那些。
