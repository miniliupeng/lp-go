# C2 GMP 调度

Go 的调度单位是 G、M、P。源码在 Go 1.27.1 的 `runtime/proc.go`、`runtime/runtime2.go` 和 `runtime/signal_unix.go`。状态数字是这份源码里的 iota，不是稳定 ABI，升级 Go 之后要重新对。

## 这一章你要会什么

能说明 G、M、P 各是什么，syscall 时 P 去了哪，本地队列空了怎么从别的 P 偷，异步抢占的信号名是什么，以及示例里的忙循环为什么不能当成信号证明。

## 三个字母

G 是 goroutine，包含栈、当前状态和要执行的函数。M 是操作系统线程。M 执行 Go 代码时要绑定一个 P。P 是调度上下文，数量约等于 `GOMAXPROCS`，每个 P 有自己的本地运行队列。`GOMAXPROCS` 默认按可用的 CPU 数来。容器里如果限额和机器核数不一致，要显式设置，否则 P 的数量会按机器而不是按限额来。

M 进入系统调用时可以放下 P，让别的 M 拿这个 P 去跑别的 G。系统调用返回后，原来的 M 再去找一个 P。找不到就让 G 回到运行队列，M 去睡觉。

`handoffp` 的注释写明：在 `findRunnable` 还能从这只 P 上找到 G 的情况下，必须有一个 M 来跑它。本地队列或全局队列还有工作时，它会 `startm`。没有工作时，还要考虑已经在找工作的 M 和空闲 P，避免无谓地再拉起线程。面试把「syscall 不占着 P，P 可以被别的 M 用」说清即可，不必背 `handoffp` 的每个分支。

网络等待走 netpoller。G 堵在 poller 上时状态是等待，不占着 P。数据到达或超时后，运行时把 G 放回运行队列。这是「很多连接不必很多线程」的原因。堵在 channel 和锁上的 G 同样不占着操作系统线程干活，占着的是 G 自己的栈。

## 本地队列和窃取

每个 P 优先跑自己的本地队列。本地队列空了，就去全局队列拿，或者执行 `runqsteal`。`runqsteal` 的注释写明：从另一个 P 的本地可运行队列偷走一半，放进自己的队列，并返回其中的一个 G。偷不到就返回 nil。

因此一个 P 上突然来了很多新 G，其它 P 会把一半一半搬走，而不是都挤在一个线程上。全局队列用来放一时没有合适本地队列的 G。新启动的 G 不一定进全局队列，运行时会尽量放进当前 P 的本地队列。

调度器还会做自旋：有的 M 醒着找工作，避免每次来一个 G 都重新创建线程。自旋太多会空转占 CPU。`findRunnable` 里把正在自旋的 M 限制在大约「忙碌 P 的一半」：`2*nmspinning < GOMAXPROCS-npidle` 时才允许再变成自旋。这是为了 `GOMAXPROCS` 很大、实际并行度很低时不要空转占满 CPU。

`findRunnable` 和 `handoffp` 的注释要求两边一致：只要前者还能找出一个 G，后者就必须拉起一个 M。一次查找的顺序，按 Go 1.27.1 这份函数的写法是：

1. 世界正要为 GC 停下来，当前 M 先停住。
2. 处理这个 P 上登记的安全点函数，并看计时器。
3. 有 trace 读取任务或 GC 标记工人时，优先跑它们。
4. 每 61 个调度节拍，如果全局队列不空，就从全局队列拿一个 G。注释说明这是为了公平：否则两个互相唤醒的 G 会一直占住本地队列。
5. 需要的话唤醒 finalizer 和 cleanup。
6. 从本地队列取。
7. 本地没有，再从全局队列一批拿走，批的大小是本地队列长度的一半。
8. 在去偷之前，做一次非阻塞的 netpoll。同时只允许一个线程在 poll，避免多核上争抢内核。
9. 仍然没有，就 `stealWork`，从别的 P 偷。偷到新的计时器或 GC 工作时，回到函数开头再找一轮。

面试不需要背第 61 这个节拍。要记住的是：本地队列优先，但会定期看全局队列；偷之前先看网络；自旋的 M 有上限。数字是实现，升级 Go 之后要重新对函数。

## G 的状态

数字来自 Go 1.27.1 的 `runtime/runtime2.go`。

| 状态 | 值 | 含义 |
| --- | --- | --- |
| `_Gidle` | 0 | 刚分配 |
| `_Grunnable` | 1 | 在运行队列上，没有在执行用户代码 |
| `_Grunning` | 2 | 可以执行用户代码，占用 M，通常还有 P |
| `_Gsyscall` | 3 | 正在系统调用，占用 M，不拥有 P |
| `_Gwaiting` | 4 | 堵在运行时里，例如 channel |
| `_Gdead` | 6 | 已退出或在空闲链表上 |

`_Gpreempted` 是 9，表示这个 G 为了 `suspendG` 自己停下来，还没有人负责把它叫醒。`_Gleaked` 是 10，表示 GC 认定它泄漏。`_Gscan` 是 `0x1000`，和上面的状态按位组合，表示 GC 正在扫这个栈。面试说到 runnable、running、syscall、waiting，并说 syscall 时不占 P，就够了。

## 抢占

goroutine 会在函数调用这类同步安全点被抢占。只靠同步安全点时，一个没有任何调用的死循环可以一直占着 P。

Unix 上还有异步抢占：`runtime/signal_unix.go` 里 `sigPreempt = _SIGURG`。运行时向线程发这个信号，让它在安全的地方放下当前 G。这是源码里的信号选择。它不是「任何一段用户代码都能在任意指令中间被打断」的许可证，运行时只在自己认定安全的点上完成抢占。

[TestBusyGoroutineYieldsP](../../../examples/c2sched/sched_test.go) 把 `GOMAXPROCS` 设成 1。忙循环调用 `atomic.Bool.Load`，这是一次函数调用，所以是同步安全点。第二个 goroutine 能在两秒内跑完。这个测试说明 P 没有被这段循环永远占住。它没有证明信号是 `SIGURG`，因为循环里已经有调用。

```bash
go test ./examples/c2sched -count=1
```

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| 一个 goroutine 对应一个操作系统线程 | M 才是线程。G 可以在 M 之间换，syscall 时 P 可以离开 |
| syscall 期间 P 一直被这个 M 占着 | `_Gsyscall` 不拥有 P |
| 本地队列空了就只能干等 | `runqsteal` 从别的 P 偷一半 |
| 示例里的原子读循环证明了 `SIGURG` | 循环里有调用，只能证明同步安全点让出了 P |
| 空的 `for {}` 在所有平台上都靠同一种信号抢占 | 异步抢占的信号以对应平台的源码为准。Unix 上这份源码是 `_SIGURG` |
| `GOMAXPROCS` 不用管容器限额 | 默认按机器的 CPU 数，可能超过容器限额 |

## 面试延伸

按 G、M、P 各一句，加上「M 执行 Go 代码需要 P，syscall 时放下 P」。然后说本地队列优先，空了就 `runqsteal` 偷一半。抢占分成同步安全点和 Unix 上的 `SIGURG`。主动声明：调用了 `atomic.Load` 的循环不是信号证明。状态数字加上「这是 1.27.1 的 iota」。

## 问答题

### 问：G、M、P 各用一句话？

G 是 goroutine，带着栈和要跑的函数。M 是操作系统线程。P 是调度上下文，上面有本地运行队列，数量约等于 `GOMAXPROCS`。M 执行 Go 代码时必须绑一个 P。

### 问：系统调用期间 P 在哪？

G 处于 `_Gsyscall`（这份源码里是 3），占用 M，不拥有 P。P 可以交给别的 M 去跑别的 G。调用返回后，原来的 M 再去找 P，找不到就把 G 放回队列。

### 问：`runqsteal` 偷多少？

注释写明偷走另一个 P 本地队列的一半，放进自己的队列，并返回其中一个 G。偷不到返回 nil。所以一个 P 上突然多出来的 G 会被别的 P 搬走，而不是永远挤在一个线程上。

### 问：netpoller 解决什么？

G 堵在网络上时不占着 P。数据到达或超时后再放回运行队列。很多连接因此不必很多线程。堵在 channel 上的 G 同样不占着线程干活，占着的是自己的栈。

### 问：四个状态的数字？

`_Grunnable` 1，`_Grunning` 2，`_Gsyscall` 3，`_Gwaiting` 4。`_Gdead` 是 6。`_Gpreempted` 是 9，`_Gleaked` 是 10，`_Gscan` 是 `0x1000`。这些是 Go 1.27.1 的 iota，不是稳定 ABI。

### 问：示例为什么不能证明 `SIGURG`？

忙循环调用了 `atomic.Bool.Load`，函数调用本身就是同步安全点。`GOMAXPROCS=1` 时第二个 goroutine 能在两秒内跑完，只说明 P 没有被这段循环永远占住。Unix 上 `sigPreempt = _SIGURG` 是源码事实，要和这个测试分开说。

### 问：没有任何调用的 `for {}` 靠什么让出 P？

同步安全点等不到调用。Unix 上运行时还可以发异步抢占信号。不要把这种循环留在测试里，它可能把 `go test` 拖住。试完要改回去。

### 问：容器里 `GOMAXPROCS` 要不要设？

默认按机器的 CPU 数。限额比机器核数小的时候，P 会比限额多，线程把限额打满。按限额设置，而不是按宿主机核数。
