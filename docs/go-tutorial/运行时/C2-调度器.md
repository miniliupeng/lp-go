# C2 GMP 调度

Go 的调度单位是 G、M、P。G 是 goroutine。M 是操作系统线程，执行 Go 代码时需要绑定一个 P。P 的数量约等于 `GOMAXPROCS`，每个 P 有自己的运行队列。M 进入系统调用时可以放下 P，让别的 M 拿去跑别的 G。

网络等待走 netpoller：G 堵在 poller 上时不占着 P。数据到达后运行时把 G 放回运行队列。这是「很多连接不必很多线程」的原因。

## G 的状态

数字来自 Go 1.27.1 的 `runtime/runtime2.go`，是源码里的 iota，不是稳定 ABI。

| 状态 | 值 | 含义 |
| --- | --- | --- |
| `_Gidle` | 0 | 刚分配 |
| `_Grunnable` | 1 | 在运行队列上，没有在执行用户代码 |
| `_Grunning` | 2 | 可以执行用户代码，占用 M，通常还有 P |
| `_Gsyscall` | 3 | 正在系统调用，占用 M，不拥有 P |
| `_Gwaiting` | 4 | 堵在运行时里，例如 channel |
| `_Gdead` | 6 | 已退出或在空闲链表上 |

`_Gpreempted` 是 9，表示这个 G 为了 `suspendG` 自己停下来，还没有人负责把它叫醒。`_Gleaked` 是 10，表示 GC 认定它泄漏。`_Gscan` 是 `0x1000`，和上面的状态按位组合，表示 GC 正在扫这个栈。面试说到 runnable、running、syscall、waiting，并说 syscall 时不占 P，就够了。

## 抢占

goroutine 会在函数调用这类同步安全点被抢占。Unix 上还有异步抢占：`runtime/signal_unix.go` 里 `sigPreempt = _SIGURG`。

[TestBusyGoroutineYieldsP](../../../examples/c2sched/sched_test.go) 把 `GOMAXPROCS` 设成 1。忙循环调用 `atomic.Bool.Load`，这是一次函数调用，所以是同步安全点。第二个 goroutine 能在两秒内跑完。这个测试说明 P 没有被死循环永远占住。它没有证明信号是 `SIGURG`，因为循环里已经有调用。

```bash
go test ./examples/c2sched -count=1
```
