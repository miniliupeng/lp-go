# C3 GC

默认垃圾回收器是并发的、精确的、非分代的、非整理的标记-清除。分配按大小分档，每个 P 有自己的缓存。这段话来自 Go 1.27.1 `runtime/mgc.go` 的文件头。

它不是 Green Tea GC。Green Tea 要 `GOEXPERIMENT=greenteagc` 才打开。默认构建使用 `internal/goexperiment/exp_greenteagc_off.go`，其中 `GreenTeaGC` 为 false。

`mgc.go` 里的周期：

1. **清扫终止**：短暂 STW，把上一轮还没扫的 span 扫完。只有这轮开始得比预期早，才会有未扫 span。
2. **标记**：STW 打开写屏障和辅助标记，把根放进队列，然后恢复。根包括栈、全局变量，以及运行时数据结构里的堆指针。扫栈时会停住对应的 goroutine。灰色对象被扫成黑色。分布式终止发现没有灰对象之后进入标记终止。标记期间新分配的对象直接是黑色。
3. **标记终止**：再一次 STW，关掉 worker 和 assist，刷新 mcache。
4. **清扫**：关掉写屏障，恢复世界。清扫和用户代码并发。清扫开始之后新对象是白色。

文件头的概述写「写屏障涂掉被覆盖的指针和新指针」。精确规则在 `runtime/mbarrier.go`：总是涂被覆盖的旧指针（Yuasa）；只有当前栈还是灰色时，才涂新指针（Dijkstra）。栈扫完变黑之后，删除屏障负责旧指针。

## GOGC 与内存上限

`GOGC` 未设置时是 100：新分配的数据达到上一轮存活数据的这个百分比，就再触发一轮。`debug.SetGCPercent(-1)` 关掉按比例触发，内存上限仍然有效。测试不调用它，避免把进程的 GC 关掉。

`debug.SetMemoryLimit` 是软上限，单位字节。运行时会提高回收频率，并更积极地把内存还给操作系统。它统计的是运行时映射和管理、尚未释放的内存，不包括 Go 二进制本身、C 代码分配的内存，也不包括不由运行时管理的 `syscall.Mmap`。文档给出的表达式是：

```text
runtime.MemStats.Sys - runtime.MemStats.HeapReleased
```

用 `runtime/metrics` 则是 `/memory/classes/total:bytes` 减去 `/memory/classes/heap/released:bytes`。传入负数只读回当前值，不修改。测试把上限设成 512 MiB，再用负数读回，结束时恢复原值。`ReadMemStats` 会短暂 STW，不要用它做高频打点。

```bash
go test ./examples/c3gc -count=1
```
