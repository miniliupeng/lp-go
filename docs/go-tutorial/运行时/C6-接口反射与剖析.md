# C6 接口、反射与剖析

方法集和 typed nil 的语言规则在 [接口](../地基/A6-接口.md)。这一章补运行时布局、反射能不能写，以及 pprof 能看见什么。示例在 [examples/c6prof](../../../examples/c6prof/prof_test.go)。

## 这一章你要会什么

能说出 `eface` 和 `iface` 的两半，能解释 `itab` 里有什么，能用 `CanSet` 判断反射能不能赋值，能选对 profile 类型，并且不把本机的 `ns/op` 当结论。

## 接口的运行时布局

空接口 `any` 是 `eface`：`_type` 指向具体类型，`data` 指向值。带方法的接口是 `iface`：`tab` 指向 `itab`，`data` 指向值。Go 1.27.1 的 `runtime/runtime2.go` 就是这两个结构。

编译器写 `itab` 时的字段是：接口类型、具体类型、一份类型哈希，以及变长的方法表 `fun`。类型 switch 用哈希缩小范围。`fun[0] == 0` 表示这个具体类型并没有实现该接口。这是编译器里的布局注释，字段会随版本调整，面试说出「接口类型、具体类型、方法表」即可。

调用接口方法就是取出 `itab` 里对应的函数指针再调用。具体类型在编译期就唯一确定时，编译器不必走这张表。

类型 `T` 的方法集只有值接收者。`*T` 的方法集两者都有。可寻址的变量调用指针方法时，编译器会自动取地址。接口里保存的是值的副本，不会再取地址。`var err error = (*missing)(nil)` 之后 `err == nil` 为 false，因为 `eface` 或 `iface` 的类型指针不是空的。

## 反射

`reflect.ValueOf(n)` 拿到的是 `n` 的副本，不可寻址，`CanSet` 为 false。`ValueOf(&n).Elem()` 走到指针指向的 `n`，可以 `SetInt`。

未导出字段即使取了地址也不能 `Set`。`CanSet` 对它是 false。反射能绕过静态类型，但绕不过导出规则。同一个包里要改未导出字段，直接写代码，不要用反射。

`Type` 和 `Value` 分开。`Type` 描述类型，`Value` 持有某个值。从接口里取出动态类型用 `reflect.TypeOf(x)`。`x` 是 nil 接口时，`TypeOf` 返回 nil。typed nil 时，`TypeOf` 返回具体的指针类型。

反射适合编码、解码、测试工具。业务分支用类型 switch 或普通函数。反射把错误推迟到运行期，也让编译器更难内联。

## pprof 能采什么

`runtime/pprof` 和 `net/http/pprof` 提供几种剖面：

| 名字 | 看见什么 |
| --- | --- |
| CPU | 按时间采样到的调用栈。没采到的短函数可以不出现 |
| heap | 分配采样。剖面里的字节数是采样估算，不是精确的收费单 |
| goroutine | 当前所有 goroutine 的栈。数量持续上涨时用来看堵在哪 |
| block | 在同步原语上等待的时间采样 |
| mutex | 抢锁等待的采样 |
| goroutineleak | Go 1.27 的剖面。堵在 channel、锁这类同步原语上，并且从可运行的 goroutine 到不了这个原语 |

`StartCPUProfile` 写出的采样在测试里不是空的。采样依赖操作系统时钟，空转太短时有可能采不到。测试忙了 50 毫秒。`pprof.Lookup("goroutineleak")` 在 Go 1.27 里不是 nil。通过全局变量还能摸到的阻塞，泄漏剖面发现不了。

`BenchmarkAdd` 只用来认识 `for b.Loop()`。终端里的 `ns/op` 留在你自己的机器上，不要写进答案。`Loop` 会把循环前的准备排除在计时之外，并阻止循环体被完全优化掉。

读火焰图时：横轴是样本占比，越宽越贵；纵轴是调用栈，下面是调用方，上面是被调用方。左右相邻不表示调用的先后。先看最宽的那几条，再看它们是业务代码还是运行时在协助 GC、复制内存。

四种常见故障和该看的剖面：

1. CPU 被空转打满。看 CPU 剖面，最宽的帧就是空转的函数。先确认那是不是预期中的忙循环，再决定加睡眠、改算法还是加缓存。
2. 大切片只留了一个小窗口。`s[:1]` 仍然引用整段底层数组，大数组回收不了。把要留下的元素 `copy` 到新切片。这是内存，不是 goroutine 泄漏。heap 剖面里看保留的对象被谁引用。
3. goroutine 堵在再也等不到的 channel 上。看 goroutine 剖面的数量和栈。`goroutineleak` 能发现其中「从可运行的 G 到不了这个同步点」的那一类。
4. 锁竞争。看 mutex 剖面。临界区里做了 RPC 时，把网络移出锁，见 [同步与原子](C5-同步与原子.md)。

剖析端点不要挂到公网。线上使用时加上认证，采完就停。CPU 剖面本身有开销。

`go tool trace` 看一段时间内的调度、GC 和系统调用。它回答「这段时间 P 在干什么」，pprof 回答「样本落在哪些函数」。两个工具解决的问题不同。

## PGO

编译器可以读一份 CPU profile 做按剖面优化，构建参数是 `-pgo`。它用剖面里的热路径决定内联，并把热的接口调用去虚拟化成直接调用。收益取决于这份 profile 是不是生产流量。不存在一个与程序无关的加速百分比。没有代表生产的 profile 时，不要打开 PGO 再把一次本地数字当成收益。

## 对比陷阱

| 说法 | 实际情况 |
| --- | --- |
| 接口值只是一个指针 | `eface` 是类型加数据，`iface` 是 `itab` 加数据 |
| `ValueOf(n).SetInt` 能改调用方的 `n` | 这个 `Value` 不可寻址 |
| 反射可以改未导出字段 | `CanSet` 为 false |
| CPU 剖面没出现的函数就是没执行 | 采样可能没采到 |
| `goroutineleak` 能找出所有泄漏 | 从可运行的 G 还能到达的阻塞不在它的定义里 |
| PGO 固定能快某个百分比 | 取决于 profile 和程序。不要背百分比 |
| 把 `BenchmarkAdd` 的 `ns/op` 写进简历 | 那是一台机器上的一次运行 |

## 运行

```bash
go test ./examples/c6prof -count=1
go test -bench=BenchmarkAdd -benchmem -run=^$ ./examples/c6prof
```

## 面试延伸

接口题画 `eface` 和 `iface`，`itab` 里有类型和方法表，typed nil 是类型非空、数据为空。反射题用 `CanSet`：副本不可写，未导出字段不可写，`&n` 再 `Elem` 可以写已导出的可寻址值。剖析题按 CPU、heap、goroutine、mutex 对上四种故障，主动说采样不是精确账单，`goroutineleak` 有它发现不了的阻塞。PGO 只说「用生产 CPU profile 指导内联和去虚拟化」，不报加速比。

## 问答题

### 问：`eface` 和 `iface` 的字段？

`eface` 是 `_type` 和 `data`。`iface` 是 `tab *itab` 和 `data`。编译器写 `itab` 时有接口类型、具体类型、类型哈希和方法表。`fun[0] == 0` 表示这个具体类型并没有实现该接口。调用接口方法就是取出方法表里的函数指针。

### 问：`ValueOf(n)` 为什么不能 `SetInt`？

`ValueOf` 拿到的是副本，不可寻址，`CanSet` 为 false。`ValueOf(&n).Elem()` 指向原来的 `n`，可以写。未导出字段即使取了地址，`CanSet` 仍是 false。反射绕不过导出规则。

### 问：`TypeOf` 对 nil 接口和 typed nil 分别返回什么？

nil 接口得到 nil。typed nil 得到具体的指针类型。这和 `err == nil` 为 false 是同一件事：类型指针不是空的。

### 问：CPU 剖面没出现的函数就是没跑吗？

不是。CPU 剖面按时间采样，很短的函数可能一次都没采到。测试里忙了 50 毫秒，是为了让采样不是空的。heap 剖面是分配采样，字节数是估算。

### 问：四种故障各看哪个剖面？

空转看 CPU，最宽的帧就是热点。大切片只留一个小窗口，看 heap 里谁还指着大数组，修复是 `copy` 出新切片。goroutine 数量上涨看 goroutine 栈。锁竞争看 mutex，并把 RPC 移出临界区。

### 问：`goroutineleak` 的定义？

堵在 channel 或锁上，并且从任何可运行的 G 都到不了这个同步点。`Lookup("goroutineleak")` 在 Go 1.27 里不是 nil。通过全局变量还能到达的阻塞，它不报。

### 问：火焰图的横轴是时间顺序吗？

不是。横轴是样本占比，越宽越贵。纵轴是栈，下面是调用方。左右相邻不表示先后。先看最宽的几条是业务代码还是运行时在协助 GC。

### 问：PGO 能承诺多少加速？

不能。`-pgo` 用 CPU profile 决定热路径的内联，并把热的接口调用去虚拟化。收益取决于 profile 是不是生产流量。没有这份 profile 时，不要把一次本地数字当成收益。

### 问：`go tool trace` 和 pprof 各回答什么？

trace 看一段时间内 P 在跑用户代码、在 GC 还是在系统调用。pprof 看样本落在哪些函数。两个问题不同，不要拿一个代替另一个。剖析端点不要挂到公网。
