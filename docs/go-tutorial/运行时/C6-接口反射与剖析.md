# C6 接口、反射与 pprof

## 方法集

类型 `T` 的方法集只有值接收者。`*T` 的方法集两者都有。可寻址的变量调用指针方法时，编译器会自动取地址。接口里保存的是值的副本，不会再取地址。typed nil 的规则在 [A6](../地基/A6-接口.md)：`var err error = (*missing)(nil)` 之后 `err == nil` 为 false。测试在 [examples/c6prof](../../../examples/c6prof/prof_test.go)。

## 反射

`reflect.ValueOf(n)` 的值不可寻址，`CanSet` 为 false。`ValueOf(&n).Elem()` 可以 `SetInt`。未导出字段即使取了地址也不能 `Set`。反射能绕过静态类型，但绕不过导出规则。

## profile

`runtime/pprof` 的 `StartCPUProfile` 写出的采样在测试里不是空的。采样依赖操作系统时钟，空转太短时有可能采不到；测试忙了 50 毫秒。不要把某台机器上的 `ns/op` 写进答案。`BenchmarkAdd` 只用来认识 `b.N`，数字留在你自己的终端里。

`pprof.Lookup("goroutineleak")` 在 Go 1.27 里不是 nil。它找的是堵在 channel、锁这类同步原语上、并且从可运行的 goroutine 到不了这个原语的泄漏。通过全局变量还能摸到的阻塞，它发现不了。

`go tool pprof` 看 CPU 和堆。`go tool trace` 看调度时间线。剖析端点不要挂到公网，见 [D4](../工程/D4-熔断重试与可观测性.md)。

```bash
go test ./examples/c6prof -count=1
go test -bench=BenchmarkAdd -benchmem -run=^$ ./examples/c6prof
```

## 练习

把 `ValueOf(n).CanSet()` 的结果和 `ValueOf(&n).Elem().CanSet()` 各用一句话讲给别人听，不要提某次 benchmark 的纳秒数。
