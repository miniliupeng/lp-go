# E2 运行时与并发

回答时先说行为，再说源码里的名字，并声明状态数字和阈值是 Go 1.27.1 的实现。不要背某次 benchmark。

## 1. GMP

G 是 goroutine，M 是操作系统线程，P 是调度上下文，数量约等于 `GOMAXPROCS`。M 执行 Go 代码需要 P。进入系统调用时 G 处于 `_Gsyscall`，占用 M，不拥有 P，P 可以交给别的 M。本地队列空了，`runqsteal` 从别的 P 偷一半。网络等待走 netpoller，等待时不占着 P。

`_Grunnable`、`_Grunning`、`_Gsyscall`、`_Gwaiting` 在这份源码里是 1、2、3、4。这是 iota，不是稳定 ABI。见 [调度器](../运行时/C2-调度器.md)。

## 2. 抢占

同步抢占发生在函数调用这类安全点。Unix 上异步抢占的信号在 `signal_unix.go` 里是 `sigPreempt = _SIGURG`。示例里的忙循环调用了 `atomic.Bool.Load`，那是同步安全点。测试只说明 `GOMAXPROCS=1` 时另一个 goroutine 还能跑到，没有证明信号。

## 3. 内存和 GC

小对象上限是 32 KiB，页是 8192，大小类 `NumSizeClasses` 为 68。分配先找当前 P 的 `mcache`，再到 `mcentral`，再到 `mheap`，最后向操作系统要页。

默认收集器并发、精确、非分代、非整理。Green Tea 要 `GOEXPERIMENT=greenteagc`，默认 `GreenTeaGC` 为 false。一轮里两次 STW：清扫终止和标记终止。标记期间新对象是黑色，清扫开始后新对象是白色。

写屏障以 `mbarrier.go` 为准：总是涂被覆盖的旧指针；当前栈仍是灰色时再涂新指针。`mgc.go` 文件头的概述写得更粗，不要用它代替这两句。

`SetMemoryLimit` 是软上限，对应 `MemStats.Sys - MemStats.HeapReleased`，或 `/memory/classes/total:bytes` 减去 `/memory/classes/heap/released:bytes`。不包括二进制、C 内存、运行时不管的 mmap。传入负数只读不改。活对象本身超过上限时收不掉。`ReadMemStats` 会 STW。

## 4. 逃逸和内存模型

返回局部变量的地址会让它活过这次调用，Go 1.27.1 的 `-m` 常写 `moved to heap`。指针不离开函数时可以留在栈上。

没有数据竞争的程序按顺序一致性理解。`go` 语句同步新 goroutine 的启动，退出不同步。发送 happens before 对应接收完成。无缓冲 channel 上，接收 happens before 对应发送完成。容量 C 时，第 k 次接收 happens before 第 k+C 次发送完成，所以缓冲可以当信号量。第 n 次 `Unlock` happens before 更后的 `Lock` 返回。失败的 `TryLock` 不建立同步。

## 5. channel

`hchan` 有计数、容量、环、发送等待队列、接收等待队列、关闭标志和锁。有人等着接收时，发送直接把值交给对方，不入缓冲。向已关闭的 channel 发送会 panic。已关闭时先取完缓冲，再接收得到零值和 `ok == false`。`close(nil)` panic。nil channel 的 `select` case 不会被选中。多个就绪 case 是伪随机。

Go 1.27 上 `time.NewTimer` 的 `C` 容量是 0。`Stop` 和 `Reset` 不会再交出过期值。高频循环里不要用 `time.After`。

## 6. context 和 WaitGroup

取消 context 不会杀掉 goroutine，函数自己看 `ctx.Err()`。`WithCancelCause` 之后 `Err` 是 `Canceled`，`Cause` 是传入的原因。`cancel(nil)` 的原因是 `Canceled`。不要用 `select` 的 `default` 和 `Done` 抢。context 的值用未导出的键类型。

`WaitGroup.Add` 要在 `Wait` 可能看到 0 之前。`WaitGroup.Go` 在函数正常返回后 `Done`。函数 panic 时，标准库把 panic 重新抛出并且不调用 `Done`。

## 7. Mutex、Pool、原子

Mutex 不可重入，不能复制。正常模式会和等待者抢。等待超过实现里的 `starvationThresholdNs`（1 毫秒）进入饥饿模式，锁交给队头。1 毫秒不是语言规范。

`Once` 的函数 panic 也算已经执行过。`Pool` 的对象可以被清掉：GC 时丢掉 victim，再把主缓存降为 victim。它不是 TTL 缓存。`sync.Map` 适合写一次读很多次，或键按 goroutine 分开。多数 map 用锁。

`atomic.Int64` 保护一个计数器。先看一个字再改另一块内存，用 `Mutex`。32 位平台用 `atomic.Int64` 保证对齐。

## 8. 接口、反射、剖面

`reflect.ValueOf(n).CanSet()` 是 false，因为这是不可寻址的副本。`ValueOf(&n).Elem()` 才可以 `Set`。未导出字段仍然不能 `Set`。

CPU 剖面是采样，heap 剖面是分配采样。goroutine 剖面看栈。`goroutineleak` 只发现堵在同步原语上、并且从可运行的 G 到不了这个原语的泄漏。大切片留一个小窗口会拖住底层数组，要用 `copy`。PGO 用生产 CPU profile 指导内联和去虚拟化，没有一个与程序无关的加速比。

## 口答题

一分钟版本：GMP 和 syscall 不占 P；写屏障的两条；channel 关闭和 nil；context 是协作取消；Mutex 不公平但有饥饿模式；typed nil 和 `CanSet`。被追问信号时，主动说示例不是 `SIGURG` 的证明。

## 追问

### 问：分配器四级和三个常数？

`mcache`、`mcentral`、`mheap`、操作系统。页 8192，小对象上限 32 KiB，`NumSizeClasses` 为 68 且 0 号不用。这些是 Go 1.27.1 源码里的数，不是语言规范。

### 问：扩容公式？

新长度大于两倍旧容量，用新长度。旧容量小于 256，翻倍。否则 `newcap += (newcap + 3*256) >> 2`，再按大小类取整。容量还够时 `append` 写进原数组。

### 问：写屏障两句？

总是涂被覆盖的旧指针。当前栈还是灰色时才涂新指针。不要用 `mgc.go` 文件头的概述代替 `mbarrier.go`。Green Tea 默认关闭。两次 STW 是清扫终止和标记终止。

### 问：channel 发送的三条归宿？

有人在等就直接交给接收方。缓冲有空位就写入环。否则阻塞发送把自己放进 `sendq`。关闭后先取完缓冲。再发送 panic。nil 的 `select` case 不会被选中。Go 1.27 上计时器通道容量是 0。

### 问：`WaitGroup.Go` panic 时调用 `Done` 吗？

不调用。panic 被重新抛出，避免 `Wait` 先返回。回调不要 panic。`Add` 要在 `Wait` 之前。

### 问：`Pool` 和缓存的差别？

GC 丢掉 victim，再把主缓存降为 victim。`Get` 不保证拿回你放进去的对象。TTL 缓存用带锁的 map 和到期时间，见工程章。`sync.Map` 不是 TTL 缓存。

### 问：`SetMemoryLimit` 不计入什么？

二进制、C 的内存、运行时不管的 mmap。公式是 `Sys - HeapReleased`。负数只读。活对象可以超过软上限。`ReadMemStats` 会 STW。
