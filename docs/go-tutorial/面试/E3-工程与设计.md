# E3 工程与设计

工程题先说本仓库真正跑过的测试，再说存储和消息的概念，并标明哪些没有连接真实的 MySQL、Redis 或 Kafka。

## 1. HTTP 超时

`ReadTimeout` 为 0 或负数表示不设超时，它包含读 body。`ReadHeaderTimeout` 为 0 时回退到 `ReadTimeout`。`IdleTimeout` 为 0 时也回退到 `ReadTimeout`。`WriteTimeout` 在读到下一个请求头时重置。四个字段都是 0 的服务器等于没有这些限制，生产不要这样留着。大文件上传不要只靠一个很短的 `ReadTimeout`。见 [HTTP 超时与关闭](../工程/D1-HTTP超时与关闭.md)。

## 2. Shutdown 和 SSE

`Shutdown` 先关监听和空闲连接，再等活跃连接回到空闲。它不打断正在跑的 Handler。context 到期返回 context 的错误。测试里 100 毫秒得到 `context.DeadlineExceeded`。`Serve` 在 `Shutdown` 被调用后返回 `ErrServerClosed`。Hijack 的连接不在等待范围内。`Shutdown` 之后这台 `Server` 不能再 `Serve`。

SSE 写 `text/event-stream`，一条事件后 `Flush`。客户端断开时 `r.Context()` 结束，处理器要返回。反压用有界队列。测试 `TestSSEStopsWhenClientCancels` 读到 `data: one` 后取消，处理器必须停。

## 3. database/sql 和 InnoDB

`*sql.DB` 是池，可以并发。`*sql.Tx` 是一条连接，不要并发。`Open` 不一定连接。`Rows` 必须 `Close`。没有行是 `sql.ErrNoRows`。

`sqltut` 不是隔离级别。同一键后提交覆盖先提交，不同键都保留，回滚丢掉 dirty。Go 1.27.1 的 `Tx.ExecContext` 打在连接上，所以连接要记住当前事务。`driver.Tx` 只负责提交和回滚。

InnoDB 另说：undo 上的版本链加 Read View 做 MVCC。RC 每次一致性读建视图，RR 在第一次一致性读建视图。普通 `SELECT` 是快照读，`SELECT FOR UPDATE` 是当前读。Next-key 是记录锁加间隙锁，用来挡幻读。覆盖索引不必回表。ICP 是回表前用索引过滤。深分页改成延迟关联或 `WHERE id > ?`。这些都不是 `sqltut` 的测试结果。

## 4. 缓存和限流

击穿是热点失效的瞬间打到数据库。穿透是键本来就不存在。雪崩是大面积同时失效。

singleflight 合并同一次在途调用，函数返回后记录删除，不留结果，所以不是缓存。负缓存针对穿透，TTL 必须短，数据库故障不能记成「没有」。令牌桶按时间补充，不超过 `burst`，再取 1。测试里速率 10、突发 2：立刻两次通过，第三次失败，100 毫秒后补充 1。这是单机桶。

cache-aside：读未命中再填；先写数据库，成功后删缓存。回填可能把旧值写回去。Redis 锁用 `SET key token NX PX`，释放时比较 token 再删。单实例锁在主从切换时可能两个客户端同时认为自己持有。本仓库没有 Redis。

## 5. 熔断、重试、消息

熔断三个状态。阈值 2、冷却 1 秒。打开期间拒绝。冷却到点放一个半开探测。探测失败重新打开并重算冷却，成功才回到关闭。示例不把 4xx 单独分类。

只重试幂等操作。重试使用入口 context 剩下来的时间，每层把剩余时间往下传，不要每层重新给满。间隔加抖动。

至少一次是处理成功后再提交偏移，崩溃会重复，所以消费端要有业务键。先提交再处理会丢。生产者确认和幂等生产者减轻丢失和重复，不代替业务键。KRaft 是元数据不再依赖 ZooKeeper，不改变分区内有序和偏移语义。本仓库没有 Kafka。

## 6. 可观测性

RED 是速率、错误、耗时。延迟看分位数，平均数会被快请求拉低。内存打点用两个 `runtime/metrics` 名字相减，名字写错是 `KindBad`，这时不能 `Uint64()`。`ReadMemStats` 会 STW。日志用 `slog`，热路径先 `Enabled`，不打密钥。pprof 不对公网。PGO 不报固定加速比。

## 7. 短链

第一个码是 `"1"`，第二个是 `"2"`：62 进制递增，`seq` 从 0 开始先加 1。字母表是 `0-9a-zA-Z`。`62^6 = 56,800,235,584`，随机仍然要处理冲突。递增码暴露顺序，线上用随机或哈希。到期时刻本身算过期。`ttl <= 0` 表示不过期。空 URL 返回错误。跳转用 302 或 307，不用 301。不要在请求的锁里扫全表。热门码加 TTL 和 singleflight。进程退出数据就没了，这是教学实现的边界。

## 8. 工具链和检索题

`go vet` 的 `stdversion` 从 Go 1.22 起按 `go.mod` 的 `go` 行判断。`go fmt` 走模块声明的工具链。Green Tea 默认关闭。`GOEXPERIMENT=nojsonv2` 是过渡开关。

检索再生成：切段并保留出处，关键词和向量两路召回，重排后把前几段交给模型，超时用入口 context，输出走 SSE。没有评测集就不要报召回率。本仓库没有向量库。

## 口答题

挑一个设计题讲五分钟时，结构固定为：数据放哪、并发怎么保护、失败和过期怎么办、哪些是教学实现故意没做的、哪些数字来自测试（`"1"`、`"2"`、突发 2、阈值 2）而不是来自没跑过的压测。

## 追问

### 问：超时四个字段的回退用一张嘴说完？

`ReadTimeout` 含 body，0 表示不限制。`ReadHeaderTimeout` 为 0 时用 `ReadTimeout`。`IdleTimeout` 为 0 时也用 `ReadTimeout`。`WriteTimeout` 在下一个请求头到来时重置。`Shutdown` 不打断 Handler，Hijack 的连接要另说。SSE 要 `Flush`，并看 `r.Context()`。

### 问：`sqltut` 和 InnoDB 怎么切开？

教学驱动同键后提交覆盖，不同键都留，没有 undo 和锁。事务语句打在连接的 Exec/Query 上。InnoDB 再讲 Read View、RC 与 RR、当前读的 next-key、覆盖索引、ICP、深分页。不要把测试结果说成隔离级别。

### 问：缓存三句话和锁的凭证？

singleflight 不留结果。负缓存要短。令牌桶的突发是 `burst`，多副本不是全局。写库成功后删缓存。Redis 锁是 `SET key token NX PX`，释放时比较 token。本仓库没有 Redis。

### 问：消息的偏移什么时候提交？

处理成功之后。这样是至少一次，要有业务键。先提交会丢。KRaft 不改变这条语义。熔断半开只放一个探测，示例不区分 4xx。

### 问：短链哪些数字是测试锁住的？

第一个码 `"1"`，第二个 `"2"`。`62^6 = 56,800,235,584`。到期时刻本身过期。跳转不用 301。进程退出数据就没了。检索题没有评测集就不要报召回率。

### 问：哪些说法不能当成结论？

某台机器的 `ns/op`。Green Tea 是默认 GC。示例里的忙循环证明了 `SIGURG`。`sqltut` 是可重复读。PGO 有一个固定的加速百分比。这些说法要么跟机器有关，要么和 Go 1.27.1 的源码、测试对不上。回答时改用本章前面的采分点。
